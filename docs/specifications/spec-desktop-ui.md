# Десктопный интерфейс и файловый IPC P5

Статус: **P5.1 реализован и проверен на Linux x64; P5.2–P5.4 уточняются перед соответствующим кодом**.
Редакция: 2026-11-25.
Основания: [план](../trackers/plan-desktop-v1.md), [архитектура](spec-architecture.md), [контракты](spec-module-contracts.md), [локальное хранение](spec-local-persistence.md).

## 1. Границы P5.1

P5.1 подключает реальную локальную сессию и окно документов: создание, множественный выбор файлов, открытие, переключение и закрытие вкладок, имена и dirty-индикатор. До P5.2 содержимое показывается как **исходный текст только для чтения**: нет временного textarea-редактора, нормализующего CRLF. Команды сохранения появляются в P5.3, внешние изменения — P5.4. Существующий Markdown-прототип остаётся отдельным стендом в памяти и не получает файловых полномочий.

Новая сессия по умолчанию TXT, UTF-8 без BOM; кнопки создания TXT и Markdown доступны явно. Пустая новая сессия не dirty. Сохранение пустого нового файла остаётся отдельной командой P5.3. Создание/переключение не пишет исходный файл. Открытие может добавить исходную историю по политике P4.

## 2. Состояние рабочего окна

- `WorkspaceApplication` в application управляет порядком вкладок, активной SessionId, именами и состояниями открытия/закрытия, используя существующий DocumentApplication. Он не знает React, Electron и пути. Это не второй владелец текста: текст/dirty/ревизии/undo находятся только в DocumentApplication.
- UI получает workspace через props и подписывается на его неизменяемый снимок (`useSyncExternalStore`). Снимок вкладки содержит SessionView, имя и closing-флаг; смена SessionView обновляет вкладку. Исключение подписчика не ломает остальных. Вкладки не скрывают другие вкладки при ошибке.
- Новые документы называются «Без имени 1.txt», «Без имени 2.md» и т. д.; счётчик не переиспользуется после закрытия. Для файлов main передаёт только `basename` и непрозрачный ref, не полный путь. Одинаковые имена допускаются: tooltip содержит имя и resourceId, а не выдуманный путь.
- Новый/opened документ добавляется справа и активируется. Повторный open того же ref активирует существующую сессию без второй вкладки/чтения; алиасы реестра подчиняются этому же правилу. Завершение открытия активирует последний успешно открытый документ выбранной пачки.
- Закрытие активной вкладки выбирает правого соседа, при его отсутствии — левого. Закрытие неактивной не меняет активную. Последняя вкладка возвращает пустой экран. Пока асинхронное закрытие не закончено, вкладка остаётся видимой; ошибка очистки черновика оставляет её открытой.
- В P5.1 закрывается только чистая сессия через DocumentApplication.close. Dirty или неизвестный исход не отбрасываются: команда сообщает ошибку и оставляет вкладку. Диалог «Сохранить / Не сохранять / Отмена» с flush редактора вводится в P5.3. В P5.1 UI ещё не создаёт несохранённого текстового ввода.
- Панель вкладок имеет tablist/tab/tabpanel, aria-selected и клавиатурное переключение стрелками/Home/End. У каждой вкладки отдельная кнопка закрытия. Dirty отмечается `●` и доступным текстом; имя не меняет DocumentId.

## 3. Открытие файлов и ошибки

«Открыть…» вызывает настоящий Electron open-dialog с `openFile`, `multiSelections`, фильтрами TXT/MD/Markdown. Нет поля произвольного пути в renderer. Отмена возвращает null и не создаёт ref/вкладку/историю. Пока запрос открыт, повторный запуск кнопки объединяется с текущим, кнопка показывает занятость; создание новых сессий допускается.

Main регистрирует каждый выбранный путь отдельно. Ответ: `{ documents: [{ ref, displayName }], errors: [{ displayName, error }] }`. Неподходящий путь не блокирует остальные файлы. Затем renderer открывает успешные ref через DocumentApplication по одному, в порядке диалога. Неудача load показывает имя/безопасную ошибку без пустой вкладки. Ошибки пачки сохраняются до следующего открытия или явного скрытия. При закрытом workspace поздний результат не добавляет вкладки.

Пустой экран предлагает создать TXT/Markdown или открыть файл. При отказе служебной БД диагностическое сообщение остаётся видимым, открытие отклоняется; пустая новая сессия в памяти допустима, но сохранность после закрытия не обещается. HTML файла всегда выводится как текст, без исполнения и сетевых запросов.

## 4. Композиция и ограниченный IPC P5.1

В main создаётся одна `createLocalServices` на профиль; клиент привязан к WebContents. Его закрытие отзывает ref и черновики. Стартовый ready-reconcile выполняется до файловых операций; неизвестный исход блокирует только свой ресурс по P4, неисправный журнал сообщает ошибку сервиса.

Добавляются только необходимые сейчас каналы/фиксированные методы preload:

| Канал | Запрос | Ответ | Метод |
| --- | --- | --- | --- |
| `dialog:open` | null | Result<OpenDialogResult или null, PortError> | pickOpen |
| `document:load` | `{ ref }` | Result<LoadedDocument, PortError> | loadDocument |
| `draft:remove` | `{ key, through }` | Result<null, PortError> | removeDraft |

`draft:remove` нужен существующему сценарию закрытия чистой сессии; это настоящая монотонная очистка P4, не успешная заглушка. Renderer-адаптер реализует эти операции; ещё не подключённые save/history/draft-put/list возвращают явный unsupported. События ресурса и файловая запись не экспортируются раньше этапов P5.3/P5.4. Диагностические app:info/storage:health сохраняются; универсальных invoke/send, файловых путей, SQL, registerPath/recoverDraft в preload нет.

Все каналы проверяют доверенный WebContents, **главный frame**, точный renderer URL, единственный аргумент и runtime-структуру DTO. В load разрешён только StorageRef из выданных этому владельцу; знание resourceId не даёт полномочий. Идентификаторы ключа/безопасное целое through проверяются и затем проходят owner-политику DraftStore. Вызов не принимает дополнительные access/path-поля. Ошибки не содержат stack/SQL/лишних путей. IPC void преобразуется в null. Ошибка транспорта возвращается как Result, не зависший Promise.

После уничтожения окна клиент отзывается немедленно, ожидающие регистрации/чтения проверяют отзыв до выдачи данных. Main учитывает незавершённые IPC-запросы: штатный выход прекращает приём, закрывает клиентов, дожидается принятых запросов и ready, затем закрывает сервисы/SQLite. В P5.1 нет публичной записи файла; дальнейший shutdown с несохранённым вводом/принятыми save уточняется в P5.3/P7. Reload renderer также заменяет клиента и отзывает старые разрешения; новый renderer не наследует ref предыдущей загрузки.

## 5. Следующие подэтапы

- P5.2: CodeMirror TXT/source, flush композиции перед переключением/закрытием, редактирование/undo/redo/поиск/замена. Данные и выделение остаются изолированными по сессиям. Полное Markdown-представление — P6.
- P5.3: диалог Save As с фактической expectedRevision существующей цели, сохранение конкретного снимка, выбор кодировки/BOM, ошибки/conflict/history-pending/unknown, подтверждение закрытия. Разрешение цели выдаёт только main; отмена ничего не меняет.
- P5.4: подписки IPC и focus-refresh, чистое перечитывание, сравнение dirty-сессии, сохранение рабочей копии при удалении. Stale-снимки/IME не заменяют новый ввод.
- Перед каждым подэтапом поведение доводится до контрактов и тестовых критериев; этот раздел не выдаётся за реализованные команды.

## 6. Приёмка P5.1

| ID | Проверка |
| --- | --- |
| DU-01 | Несколько новых TXT/MD, монотонные имена, переключение/закрытие активной и неактивной вкладки, возврат пустого экрана |
| DU-02 | Отмена диалога не меняет список; частичный отказ не блокирует другие файлы; повтор/алиас не дублирует вкладку |
| DU-03 | Точные UTF-8/Windows-1251/смешанные переводы строк показаны в read-only source, HTML не исполняется, пользовательские байты не меняются |
| DU-04 | Dirty-индикатор следует SessionView; dirty/ошибка очистки не закрывают вкладку молча; подписки освобождаются |
| DU-05 | Настоящий IPC отклоняет невыданный ref, path/extra-поля, нецелую ревизию, чужое окно/subframe и устаревший ref после reload |
| DU-06 | Закрытие окна/выход во время ожидающего диалога/чтения отзывает доступ и не закрывает SQLite раньше запроса |
| DU-07 | Unit/application, native/router и GUI dev/packaged; регрессия Markdown-прототипа и исключение тестовых бандлов из asar |

GUI-тесты подменяют только функцию Electron dialog в main через Playwright, чтобы воспроизводить выбранные пути и отмену; отдельного production test-IPC/переменных с разрешённым путём нет. Сам вызов showOpenDialog остаётся настоящим API Electron, но взаимодействие с системным диалогом вручную на каждой ОС остаётся открытым в P8. Проверки Linux не закрывают Windows/macOS.
