# Редактирование Markdown и проверочный прототип

Статус: **ранний прототип P3 проверен на Linux x64; полный редактор и оптимизация — P6**.
Редакция: 2026-11-25.
Основания: [модель документа](spec-document-model.md), [контракты модулей](spec-module-contracts.md), [архитектура](spec-architecture.md).

Документ определяет интеграцию редакторов и проверку P3. Полная панель команд, работа с физическими вложениями и окончательная компоновка UI реализуются в P6 в рамках этого контракта.

## 1. Основа интеграции

- CodeMirror 6 отображает исходный текст; ProseMirror — визуальное представление GFM.
- `remark-parse` и `remark-gfm` дают структуру и исходные позиции. Парсер не является сериализатором всего документа при каждом изменении.
- Один `DocumentSession` владеет текстом, undo/redo и ревизиями. Локальные изменения движка подтверждаются общей сессией.
- Для обычных документов в прототипе допустим полный повторный разбор. Сериализация изменений ограничена затронутыми исходными диапазонами.

## 2. Контракт редактора

Типы интеграции принадлежат `ui/editors`. Они не импортируются в `core` или `formats`.

```ts
import type {
  EditState, EditTransaction, SessionId, SourceSelection, Result,
} from './spec-document-model';
import type { CommandError } from './spec-module-contracts';
import type { ParsedMarkdown } from '../../src/formats';

export type EditorMode = 'source' | 'visual';

export interface EditorFrame {
  readonly sessionId: SessionId;
  readonly state: EditState;
  readonly selection: SourceSelection;
  readonly editable: boolean;
  readonly canUndo: boolean;
  readonly canRedo: boolean;
  readonly markdown?: ParsedMarkdown;
}

export interface EditorHost {
  dispatch(transaction: EditTransaction): Result<EditorFrame, CommandError>;
  undo(): Result<EditorFrame, CommandError>;
  redo(): Result<EditorFrame, CommandError>;
  selectionChanged(selection: SourceSelection): void;
  compositionChanged(active: boolean): void;
  reportError(error: CommandError, pendingInput: string | null): void;
  requestSource(selection: SourceSelection): void;
}

export interface EditorInstance {
  render(frame: EditorFrame): void;
  flush(): Promise<Result<void, CommandError>>;
  focus(): void;
  destroy(): void;
}

export interface EditorFactory {
  readonly mode: EditorMode;
  mount(element: HTMLElement, host: EditorHost, initial: EditorFrame): EditorInstance;
}

export type PrototypeFormatAction =
  | { readonly kind: 'set-inline'; readonly mark: 'strong' | 'emphasis' | 'strike';
      readonly enabled: boolean }
  | { readonly kind: 'set-heading'; readonly level: 1 | 2 | 3 | 4 | 5 | 6 }
  | { readonly kind: 'set-task'; readonly checked: boolean };
```

Форматирующая команда получает текущий снимок и выделение и формирует `EditTransaction`. Команды из последнего типа задают минимальные действия прототипа, а не полный список функций первой версии.

### 2.1. Поток правки

1. Редактор получает `EditorFrame` с исходным текстом, обеими ревизиями и выделением.
2. Пользовательское действие преобразуется в транзакцию с `baseStateRevision` этого кадра. Диапазоны относятся к исходному тексту, а не к координатам DOM/ProseMirror.
3. `host.dispatch` синхронно проверяет и применяет транзакцию через приложение и ядро.
4. При успехе возвращённый кадр становится подтверждённым состоянием редактора. `render` этого кадра не создаёт нового пользовательского изменения.
5. При ошибке редактор не считает свой локальный результат сохранённым в модели. Незавершённый ввод остаётся доступен до пересчёта действия или разрешения конфликта.

Движки не записывают файлы, не создают версии и не управляют таймерами авточерновиков. Undo/redo вызывают host, включая горячие клавиши и команды контекстного меню.

### 2.2. Курсор, переводы строк и IME

- SourceSelection задаётся UTF-16-позициями исходного текста. Сохраняется направление выделения anchor/head.
- Адаптер CodeMirror учитывает различия между своими разделителями строк и исходными LF/CRLF/CR. Неизменённые исходные переводы строк остаются прежними.
- Адаптер ProseMirror хранит отображение текстовых позиций, структурных границ и исходных диапазонов. Для неоднозначной границы используется привязка до/после видимого элемента. Курсор не оказывается внутри суррогатной пары или CRLF.
- Неотображаемые маркеры Markdown имеют исходные диапазоны; отсутствию отдельного визуального символа не соответствует потеря исходника.
- Во время IME-композиции промежуточный ввод может оставаться внутри движка. На завершении он передаётся одной атомарной транзакцией и одной группой undo.
- Пока композиция активна, смена режима, сохранение, внешнее перечитывание и закрытие ожидают `flush`. `flush` завершает или дожидается штатного завершения композиции; ошибка не разрешает уничтожить редактор с незавершённым вводом.
- Если исходное состояние успело измениться, композиция не применяется по устаревшим координатам. Её текст сохраняется в живой интеграции для разрешения конфликта. Прототип обязан воспроизвести этот случай.

### 2.3. Переключение режима

Вызвать `flush` → сохранить выделение в исходных координатах → завершить группу undo → создать другой редактор с актуальным кадром → восстановить выделение по доступной привязке. Внутренняя разметка HTML/ProseMirror не используется как новое содержимое документа.

Если позиция находится внутри неподдерживаемого фрагмента, визуальный режим выделяет его защищённое представление; исходный режим возвращает точную исходную позицию. Стек undo не сбрасывается.

`destroy` освобождает слушателей и DOM; он вызывается после успешного flush или явно подтверждённого отбрасывания ввода.

## 3. Затронутый фрагмент

Минимальная единица правки определяется действием:

| Действие | Допустимый участок изменения |
| --- | --- |
| Ввод/замена видимого текста | Его исходный диапазон с необходимым экранированием |
| Inline-форматирование | Выделенный текст и его изменяемые маркеры |
| Уровень заголовка | Строка заголовка |
| Checkbox задачи | Маркер checkbox конкретного пункта |
| Правка содержимого списка | Соответствующий пункт; соседние маркеры и нумерация сохраняются |
| Текст ячейки | Содержимое ячейки; структурные изменения таблицы могут затронуть всю таблицу |
| Alt изображения / метка ссылки | Соответствующий исходный атрибут или метка |

Для структурной операции допустимо расширить участок до минимального синтаксически связного контейнера. Такое расширение должно быть определено конкретной командой, а не происходить незаметно при каждом вводе.

Вне изменяемых диапазонов символы сохраняются точно. Внутри диапазона допустима нормализация, но ожидаемый исходник проверочных примеров ниже фиксирован. Изменение определения reference-ссылки требует обновления визуального представления связанных ссылок, но не переписывания их исходных употреблений.

Неподдерживаемые узлы сохраняют исходный фрагмент и отображаются как защищённый блок с переходом к исходнику. В прототипе встроенный HTML отображается как исходный фрагмент, а не исполняемый DOM. Изображения прототипа используют тестовый resolver; внешняя сеть не требуется для прохождения примеров.

## 4. Проверочные примеры

Машиночитаемые данные: [spec-markdown-cases.json](fixtures/spec-markdown-cases.json).

Каждый пример содержит `source`, действие, точный `expected` и `changeScope`. `changeScope: null` требует полного равенства. Иначе scope — единственная подстрока исходника, внутри которой разрешены изменения; префикс и суффикс вне неё должны остаться идентичными.

`select` в действии — единственная подстрока исходника, используемая тестовым драйвером для задания выделения. Тест взаимодействует с визуальным редактором и командами host; прямая подмена текста на expected не проверяет интеграцию.

| ID | Что проверяется |
| --- | --- |
| MD-01 | Несколько переключений полного GFM-документа без правок |
| MD-02 | Жирное выделение слова рядом с другим стилем исходных маркеров |
| MD-03 | Checkbox вложенной задачи при сохранении окружающего списка |
| MD-04 | Ячейка таблицы с сохранением соседнего текста и исходного оформления |
| MD-05 | Сохранение неизвестного HTML при правке соседнего абзаца |
| MD-06 | Блок кода с четырьмя backtick-маркерами и CRLF |
| MD-07 | Обычный текст рядом с неизвестной директивой |
| MD-08 | Метка reference-ссылки с сохранением определения и регистра ID |
| MD-09 | Emoji, комбинируемый знак, отсутствие Unicode-нормализации |
| MD-10 | Список с нестандартной исходной нумерацией и `)` |
| MD-11 | Alt изображения с относительным путём и title |
| MD-12 | Изменение уровня заголовка внутри его строки |

Для каждого изменяющего примера: исходник → визуальное действие → ожидаемый исходник → смена режима → undo до исходника → redo до expected. Ни переключение, ни undo/redo не обращаются к хранилищу.

## 5. Дополнительные проверки прототипа

| ID | Последовательность и критерий |
| --- | --- |
| ME-01 | Программный render нового кадра не вызывает dispatch: нет цикла обновлений |
| ME-02 | Старая транзакция после новой правки отвергается, новый текст сохраняется |
| ME-03 | Метаданные меняются при прежнем тексте: кадр получает новую stateRevision, разбор текста можно переиспользовать |
| ME-04 | IME вводит несколько промежуточных состояний: commit одна группа, undo удаляет завершённую композицию целиком |
| ME-05 | Сохранение/смена режима во время композиции ждут flush и включают подтверждённый ввод |
| ME-06 | Курсор и выделение переживают переключение около ссылок, emoji и CRLF без некорректных позиций |
| ME-07 | Удаление/вставка соседнего блока сохраняет неподдерживаемый исходный фрагмент |
| ME-08 | Последовательные source- и visual-правки отменяются в общей обратной последовательности |
| ME-09 | Наборы обычных документов 10 КБ, 100 КБ и 1 МБ: измерены разбор, переключение и задержка ввода; нет зависания или потери правок |

Размеры в ME-09 — тестовый набор, а не лимит продукта. В отчёте фиксируются окружение, размеры, измерения и замеченные ограничения, без утверждения непроверенной производительности.

## 6. Результат P3

В `docs/trackers/track-markdown-prototype.md` фиксируются версии редакторов и парсера, результаты MD/ME-проверок, ограничения и выбранный способ преобразования правок. Для неподтверждённого случая записываются воспроизведение и причина.

Этап завершён, когда согласованные свойства сохранения исходника и общей истории подтверждены. Если нужна замена интеграции или движка, решение сначала обновляется в документации. Примеры этого документа описывают проверку; их наличие не означает прохождения P3.

Фактический результат P3: [отчёт прототипа](../trackers/track-markdown-prototype.md). Связка подтверждена в описанных границах; полный разбор даёт заметную задержку на 1 МБ, которую необходимо устранить до завершения P6. Реальные системные IME/остальные ОС не считаются проверенными по результатам Chromium/CDP.

## 7. Решение реализации P3 (2026-11-24)

- Прототип открывается отдельной кнопкой из каркаса. Это явно обозначенный стенд в памяти: загрузка тестового текста, два режима, минимальные команды, просмотр точного исходника, undo/redo и проверка снимка после flush. Файлы пользователя и SQLite истории он не изменяет. Адаптер памяти переносится из tests/support в platform/memory и остаётся проверенным тем же контрактным набором.
- `formats/markdown` использует unified/remark-parse/remark-gfm, хранит AST с UTF-16-позициями и чистые команды ограниченных замен. ProseMirror и DOM не импортируются в formats. Его дерево строится в ui/editors вместе с двунаправленной картой исходных текстовых фрагментов. Полной сериализации PM-документа нет.
- В прототипе отображаются абзацы, заголовки, inline-стили/ссылки, цитаты, списки/задачи, GFM-таблицы и fenced code. HTML, определения ссылок и распознанные блоки неизвестных директив — защищённый исходный текст. Неоднозначное отображение не даёт права переписать исходник: операция отклоняется с переходом к source. Полные структурные команды и остальные конструкции уточняются в P6.
- Source CodeMirror использует нормализованное внутреннее представление переводов строк и отдельную карту до исходника. Вставляемые новые переводы берут стиль документа; неизменённые LF/CRLF/CR не переписываются. Визуальные вставки экранируют Markdown-пунктуацию в обычном тексте и `|` в ячейках; код не экранируется. Курсор/выделение не попадают внутрь entity, surrogate или CRLF.
- CodeMirror создаёт CSS и размеры элементов во время работы. Production CSP разрешает inline **стили**, но по-прежнему запрещает inline **скрипты**, сеть, вложенные frame и навигацию. Непроверенный HTML документа не превращается в DOM; отдельная регрессия проверяет именно script-src, не запрещая нужные редактору стили.
- Минимальные visual-транзакции преобразуются через карту диапазонов: ввод/удаление в текстовом листе, команды inline, checkbox, уровень heading и редактирование alt через отдельное поле. Неизвестная структурная транзакция не сериализуется автоматически. Ссылки не запускают навигацию; изображения показывают встроенный безопасный placeholder, без запросов к сети/файлам. Это не реализация вложений P6.
- Обычный `beforeinput/insertText` в visual перехватывается до изменения DOM и превращается в исходную правку. Это исключает промежуточное удаление выделения до вставки (в частности в code block). Композиционные события не перехватываются как обычный ввод. Пустое визуальное выделение использует одну привязку для anchor/head, чтобы скрытый Markdown-маркер между соседними листьями не стал ложным выделением.
- Контроллер связывает одну application-сессию с активным редактором. Программный render не вызывает dispatch. Контроллер не выполняет повторный render посреди синхронного dispatch библиотеки; команды undo/redo направлены только в application. При неоднозначном визуальном положении сохраняется точное исходное выделение до реального движения пользователя.
- После первых замеров устранён повторный разбор одной ревизии: необязательный `EditorFrame.markdown` передаёт неизменяемое по договору производное дерево из контроллера в visual. Получатель проверяет и sourceRevision, и точный текст перед переиспользованием; при несовпадении строит свежий разбор. Это данные UI, они не входят в каноническую модель/IPC и не сериализуются обратно в Markdown. Абзац с неизвестным inline HTML защищается целиком, пока не реализовано точное редактирование такого смешанного фрагмента в P6.
- Композиция удерживается в живом движке до завершения и передаётся одной транзакцией. Flush ждёт compositionend, а не уничтожает ввод. Если фон изменил stateRevision, транзакция отклоняется, неподтверждённый текст остаётся в движке и видимом поле восстановления; смена режима/снимок блокируются. Отбрасывание возможно только явной кнопкой. `reportError` передаёт ошибку и этот текст, `requestSource` запрашивает переход для защищённого фрагмента.
- Автотесты используют настоящий DOM редакторов и команды панели; expected из fixtures служит только проверкой результата. IME проверяется событиями Chromium/CDP с отдельной фиксацией того, что это не ручная проверка системного IME всех ОС. Размерные замеры фиксируются отдельно, без обещаний до измерения.
- Поле стенда умеет принимать JSON-строку и показывает исходник также в JSON: обычный HTML textarea нормализует CRLF/CR при вводе и чтении value. JSON применяется только для точной загрузки/наблюдения стенда, не становится форматом документа или обходом действий редактора.
