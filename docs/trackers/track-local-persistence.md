# Локальное хранение P4: прогресс и проверки

Начало: 2026-11-25.
Статус: **P4.1 завершён; читающая часть P4.2 и запросы исходной истории реализованы, записывающая часть P4.2/P4.3 впереди**.
Основания: [спецификация хранения](../specifications/spec-local-persistence.md), [план](plan-desktop-v1.md).

## 1. Принятые решения P4.1

- Ресурс идентифицирует место хранения, DocumentId — рабочую линию документа. Save As сохраняет DocumentId, но не переносит историю старой цели. Прежнее содержимое подтверждённой существующей цели сохраняется до замены.
- История получает исходную версию существующего файла при первом открытии. Хранятся пять последних состояний, включая последнее; одинаковые соседние снимки не дублируются, A → B → A остаётся тремя состояниями.
- Кодировки определяются консервативно: строгий UTF-8, затем проверяемая Windows-1251; UTF-16/32 и NUL не поддерживаются. Подсказка реестра encoding/BOM применяется только при совпавших байтах. Нормализации текста/переводов строк нет.
- Сохранение связывает файловую замену с журналом SQLite; unknown отличается от not-written и history-pending. Восстановление не публикует temp поверх неизвестного внешнего состояния. Неопределённая старая запись блокирует дальнейшую автоматическую запись той же цели, но не Save As в другой ресурс.
- Реестр, история, журнал, черновики и границы очистки разделены; схема v2, миграции, состояния восстановления, права/алиасы и ограничения ОС описаны до кода.

Это проектные правила. Их наличие в спецификации не означает готового сохранения: большая часть сценариев P4 ещё не реализована.

## 2. Реализованный фундамент P4.2

- [Кодек](../../src/platform/desktop/main/persistence/codec.ts): iconv-lite 0.7.3, точные UTF-8/Windows-1251/BOM, round-trip, сохранность Unicode и переводов строк. Непредставимый текст не превращается в `?`. Неопределённый CP1251-байт `0x98` запрещён отдельно: iconv-lite отображает его в U+FFFD и обратно, из-за чего простой round-trip пропускал бы ошибку. Намеренный U+FFFD в UTF-8 разрешён.
- [Чтение файла](../../src/platform/desktop/main/persistence/file-reader.ts): один descriptor, stat до/после, проверка пути и длины, SHA-256 всех байтов и версионированная ревизия с inode/временами/правами. Обнаруженная гонка не возвращает частичный документ. Ссылки/каталоги не читаются как обычный файл; descriptor закрывается и при отказе.
- [SQLite](../../src/platform/desktop/main/database.ts): миграция v1 → v2 с пятью таблицами, FK, JSON/check-ограничениями и единственной активной операцией на ресурс. WAL + synchronous FULL + foreign_keys + busy_timeout проверяются health-транзакцией. Ошибка миграции не сбрасывает исходные данные, недостающая таблица не создаётся поверх объявленной готовой схемы.
- `storage:health` теперь возвращает схему **2**. Существующий ограниченный bridge не расширялся; renderer по-прежнему не имеет файловых полномочий.
- [Реестр путей](../../src/platform/desktop/main/persistence/path-registry.ts): канонические существующие пути и отсутствующие save-target, повторная/параллельная регистрация, символьные алиасы и сохранение case-sensitive имён. Внешний rename не переносит старую историю по inode; разные hard-link пути доступны для чтения отдельно.
- [Репозиторий](../../src/platform/desktop/main/persistence/repository.ts): реестр и проверяемые JSON v1, исходная версия + счётчик + метаданные чтения в одной SQLite-транзакции; запросы истории с проверкой hash/Unicode/метаданных и безопасных чисел. Неизвестная версия/порча не маскируются пустой историей. ServiceDatabase выдаёт соединение только main-репозиториям.
- [Читающие сервисы](../../src/platform/desktop/main/persistence/local-read-services.ts): ref-разрешения на владельца, отзыв и при отложенном чтении, стабильные DocumentId/resourceId после переоткрытия, `documents.load` и `history.list/read`. Регистрация пути остаётся main-only; это `Pick<DocumentStore, 'load'>`, а не полный порт с временной небезопасной записью.
- [Очередь ресурса](../../src/platform/desktop/main/persistence/queue.ts): разные владельцы разделяют последовательность одного ресурса, независимые ресурсы не блокируются; отказ задачи не отравляет следующий вызов. Фабрика переиспользуется для одного соединения. Подключение к жизненному циклу настоящего WebContents/IPC следует в P5.

## 3. Фактические проверки

Linux x64, Electron 45.4.1 / Node 24.22.3 / ABI 150; инструментальный Node 24.11.1. Другие ОС не проверялись.

### 3.1. Начальный шаг: кодек/reader/схема (до реестра)

- `TMPDIR=/tmp/opencode npm run check`: **144 unit-теста** в 8 файлах, типы domain/main/renderer, lint, границы и форматирование.
- Новые [24 теста кодека](../../tests/unit/local-codec.test.ts) и [14 тестов чтения](../../tests/unit/local-file-reader.test.ts) выполняются через Vitest в **инструментальном Node**, не выдаются за нативную проверку ФС под Electron. Проверены каждый определённый ненулевой CP1251-байт, U+FEFF/U+FFFD, суррогаты, BOM, NFC/NFD, смешанные окончания строк, одинаковая длина с прежним mtime, смена inode, подмена/удаление при чтении, неполный буфер, ошибки чтения/close и копирование подсказки до await.
- `TMPDIR=/tmp/opencode npm run test:native`: **10 проверок SQLite внутри Electron**, включая новую/старую/некорректную схему, откат частичной миграции, FK/ограничения, переоткрытие записей истории/журнала/черновиков/границ очистки. Это проверка схемы и долговечности строк, не реализация поведения портов истории/черновика.
- `npm run dist:dir`: сборка и распакованная Linux-поставка получены.
- По **2 GUI-регрессии каркаса** прошли в dev и packaged: IPC/sandbox/single-instance/нативная SQLite в собственном asar, схема 2 и отказ повреждённой БД без сброса. При первом прогоне тест ещё ожидал старую подпись «схема 1»; ожидание обновлено, оба набора повторно прошли.
- Markdown GUI-набор P3 в этом шаге повторно не запускался: редакторы и их интеграция не менялись. Его прежние результаты не обозначаются новым прогоном P4.
- Production `npm audit --omit=dev`: 0 уязвимостей. Полная установка по-прежнему сообщает 6 moderate-позиций инструментов сборки, ранее отмеченных в P1; небезопасный `audit fix --force` не применялся.
- Документация: 14 Markdown-файлов, 131 локальная ссылка, 45 уникальных задач (20 завершены); три извлечённых TypeScript-контракта компилируются. Markdown-fixtures не менялись, package.json/lockfile согласованы, `git diff --check` без ошибок.

Команды GUI-проверки после `dist:dir`:

```sh
TMPDIR=/tmp/opencode NEWEDITOR_TEST_DEV=1 npm run test:electron -- tests/electron/desktop.spec.mjs --output=/tmp/opencode/neweditor-p4-foundation-dev
TMPDIR=/tmp/opencode NEWEDITOR_EXECUTABLE="$PWD/dist/linux-unpacked/neweditor" npm run test:electron -- tests/electron/desktop.spec.mjs --output=/tmp/opencode/neweditor-p4-foundation-packaged
```

### 3.2. Реестр и читающие сервисы

- Повторный `TMPDIR=/tmp/opencode npm run check`: **148 unit-тестов** в 9 файлах; добавлены 4 проверки порядка/независимости/ошибок очереди. Типы, lint, границы модулей и форматирование прошли.
- `TMPDIR=/tmp/opencode npm run test:native`: **46 проверок внутри Electron** — прежние 10 проверок схемы и 36 проверок реестра/ФС/репозиториев, включая вложенные случаи. Новый [набор](../../tests/native/local-persistence.test.ts) собирается существующим Vite в `out/native-tests`, затем запускается `node:test` бинарником Electron. Оба набора явно проверяют runtime Electron; это не запуск только в инструментальном Node.
- Проверены: начальная история и отсутствие дубликата при повторе/внешнем чтении; стабильность ref/DocumentId и утрата разрешений после перезапуска; изоляция владельцев; отзыв ожидающего чтения; атомарный rollback ошибки после INSERT версии; работа после отказа; активный журнал без скрытого изменения метаданных; неизменность пользовательских байтов; UTF-8 BOM/Windows-1251; существующая/отсутствующая цель; символьные ссылки, FIFO, hard links, подмена родительского каталога, inode-замена и внешний rename.
- История читается после удаления файла и не выдаёт версию чужого ресурса; порядок проверен по sequence при обратном ходе часов. Для проверки нескольких исторических записей строки добавлены тестом напрямую в SQLite: это **не** свидетельство готового save или лимита пяти версий. Повреждённые/неизвестные JSON, неверный hash, суррогат и небезопасное целое дают ошибку, а не новую/пустую историю.
- Case-sensitive пути проверены на доступной Linux ФС; наличие условной проверки алиасов в тесте не доказывает поддержку case-insensitive macOS/Windows. Матрица остальных ОС остаётся открытой.
- Повторно получена `dist:dir`, по **2 GUI-регрессии каркаса** dev/packaged прошли. Bridge по-прежнему предоставляет только две диагностические функции, SQLite работает из собственного asar. Сами читающие сервисы ещё не подключены в production composition/renderer; их нативная проверка не обозначается GUI-путём файлового редактора.
- При введении тестового бандла обнаружена слишком широкая упаковочная маска `out/**`. Теперь electron-builder включает только main/preload/renderer; GUI-регрессия packaged дополнена проверкой отсутствия `out/native-tests`. Повторная упаковка и просмотр app.asar подтвердили наличие трёх runtime-каталогов и отсутствие native-tests/прочих out-артефактов. В dev тестовый каталог существует — это отдельно видно в диагностике, но в поставку он не попадает.
- Markdown GUI-набор не повторялся: UI и редакторы не менялись. Прежние показатели P3 не объявляются новой проверкой P4.
- Итоговая согласованность: 14 Markdown-файлов, 137 локальных ссылок, 45 уникальных задач (20 завершены); три TypeScript-контракта компилируются, fixtures неизменны, package.json/lockfile согласованы, `git diff --check` без ошибок. Завершённость P4.2/P4.3 не завышена по результатам читающего подэтапа.

Команды GUI-регрессии текущего шага аналогичны разделу 3.1, output — `/tmp/opencode/neweditor-p4-registry-dev` и `/tmp/opencode/neweditor-p4-registry-packaged`.

## 4. Что ещё не готово

- Полный `DocumentStore` ещё не готов: save/getOperation/reconcile должны появиться вместе с журналом, не как незащищённая промежуточная запись. Поэтому P4.2 остаётся незавершённой несмотря на готовое чтение/реестр/очередь. Публичного файлового IPC и подключения к UI пока нет.
- Реализованы исходная история и её чтение, но политика сохранений/удержания пяти версий и репозиторий черновиков ещё впереди. Пользовательские файлы не сохраняются; прототип Markdown остаётся memory-only.
- Журнал prepared/replacing/file-written/settled/needs-attention пока только описан и имеет таблицу. Реальная запись, reconcile, принудительное прерывание процесса и восстановление — P4.3/P4.6.
- Наблюдение/polling, подавление событий своей записи и общий memory/local load/save-контрактный набор ещё впереди. Чтение/FIFO/подмена родителя уже проверены под Electron, но гонки/сбои каждой границы **записи** и прерывание main остаются для P4.6.
- История/черновики/восстановление через UI — P5/P7; изображения/Markdown Save As — P6. Нельзя считать этот шаг завершением всего P4.

Следующий шаг: завершать **записывающую часть P4.2 совместно с P4.3** — SaveRequest/expectedRevision, журнал, temp/replace и идемпотентное reconcile. Затем довести политику истории P4.4 и черновики/наблюдение P4.5. Отдельный небезопасный save без журнала не вводится ради отметки задачи.
