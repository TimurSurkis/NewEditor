# План-трекер: десктопная версия 1

Статус: **P4 и P5.1–P5.4 завершены на Linux x64; P5 в работе**.
Дата создания: 2026-11-21.
Текущая задача: **P5.5 — сквозная приёмка TXT, нескольких вкладок, кодировок и ошибки записи**.
Состояние реализации: открытие/редактирование/поиск/сохранение/кодировки и закрытие подключены к файловым сессиям. Внешние изменения перечитывают чистый документ, dirty-конфликт сохраняет рабочий текст для сравнения/явного принятия внешней версии/Save As; удалённая копия не теряется. Авточерновики и восстановление введённого текста после краша ещё не подключены к UI (P7).
P4 закреплён коммитами `0d23ded` и `5fb91b7`, P5.1 — `341de78`, P5.2 — `60189c8`, P5.3 — `d33df8b`. Завершённый P5.4 фиксируется отдельным коммитом по правилу пользователя; push — по отдельной просьбе.

Основания:

- [Концепция проекта](../concepts/concept-project.md).
- [Архитектура и выбранные инструменты](../specifications/spec-architecture.md).

Пользователь выбрал TypeScript, актуальный стабильный Electron и SQLite, а остальные решения делегировал исполнителю. Исполнитель принимает решения в рамках согласованных требований, фиксирует их в спецификациях и затем реализует соответствующий этап.

## 1. Результат первой версии

Electron-приложение для Windows, macOS и Linux, которое:

- открывает локальные TXT и Markdown из любого места на диске;
- работает с несколькими документами во вкладках;
- редактирует исходный текст и Markdown в визуальном режиме;
- сохраняет нетронутую Markdown-разметку и неподдерживаемые фрагменты;
- предоставляет панель форматирования, поиск и замену, отмену и повтор действий;
- поддерживает UTF-8 и Windows-1251;
- сохраняет файлы явно, ведёт историю пяти сохранённых состояний и отдельные авточерновики;
- позволяет просмотреть, сравнить и восстановить версию;
- обнаруживает внешние изменения и восстанавливает данные после сбоя;
- сохраняет вставленные изображения рядом с Markdown в папке вложений.

Облачная версия и расширение форматов следуют этапам, описанным в концепции. Этот трекер управляет первой десктопной поставкой.

## 2. Принятые решения для выполнения плана

Полные версии инструментов и источники проверки приведены в архитектуре, раздел 1.1.

| Область | Решение |
| --- | --- |
| Язык | TypeScript со строгой проверкой типов |
| Разработка и сборка | Electron stable, electron-vite + Vite, React |
| Упаковка | electron-builder |
| Зависимости | npm, один проект, точные версии прямых зависимостей и `package-lock.json` |
| Локальная БД | SQLite через `better-sqlite3`, SQL и миграции в платформенном модуле |
| Исходный редактор | CodeMirror 6 |
| Визуальный Markdown | ProseMirror с собственным преобразованием действий в изменения исходного текста |
| Разбор Markdown | `remark-parse` + `remark-gfm`, исходные позиции узлов сохраняются |
| Кодировки | `iconv-lite` в адаптере файлов |
| Состояние интерфейса | Сессии приложения и подписка React через `useSyncExternalStore` |
| Стили | CSS Modules |
| Проверки | Vitest для чистой логики; Playwright для UI и Electron-сценариев |

Связка редакторов проверяется в P3 до полноценной интеграции визуального режима. Если конкретная библиотека не позволяет выполнить требования, исполнитель фиксирует результаты прототипа и выбирает замену, сохраняя архитектурные контракты и требования к Markdown.

Принятые значения по умолчанию:

- Пять версий включают последнее сохранённое состояние; доступно до четырёх более ранних сохранений.
- Новый файл — UTF-8 без BOM. Представление существующего файла сохраняется при обычном сохранении; подробности кодировок и переводов строк закрепляются в P4.
- Авточерновик записывается после одной секунды без правок; при непрерывном вводе — не реже одного раза в пять секунд. Это отдельная запись от сохранённого файла и его версий.

## 3. Правила ведения трекера

- `[ ]` — задача ещё не завершена; `[x]` — результат получен и проверен.
- Состояние этапа: `готов к началу`, `запланирован`, `в работе`, `заблокирован`, `завершён`.
- Перед кодом этапа исполнитель доводит указанную спецификацию до достаточной точности и фиксирует принятые решения.
- Завершённая задача сопровождается ссылкой на результат и краткой записью о проверке в журнале выполнения.
- У этапа обновляются состояние и следующий шаг. Невыполненная проверка остаётся явно отмеченной.
- Тестируются значимые свойства: сохранность данных, преобразование Markdown, контракты и пользовательские сценарии.
