# Десктопный интерфейс P5: прогресс и проверки

Начало: 2026-11-25.
Статус: **P5.1–P5.5 завершены на Linux x64; P6.1 зафиксирован, текущая реализация P6.2**.
Основания: [спецификация UI](../specifications/spec-desktop-ui.md), [план](plan-desktop-v1.md), [контракты](../specifications/spec-module-contracts.md), [результаты P4](track-local-persistence.md).

## 1. Результат P5.1

- [WorkspaceApplication](../../src/application/workspace.ts) управляет вкладками поверх DocumentApplication: монотонные имена новых TXT/MD, порядок/активная вкладка, частичные ошибки открытия, активация прежнего ref без дубликата, выбор соседа после закрытия, dirty/closing-индикаторы и очистка подписок. Текст и ревизии не дублируются: вкладка ссылается на неизменяемый SessionView.
- [UI вкладок](../../src/ui/components/Workspace.tsx) предоставляет создание TXT/Markdown, открытие, переключение мышью/стрелками/Home/End и отдельные кнопки закрытия. Исходник показывается **только для чтения** в pre как текст, включая CRLF/CR/NFC/NFD. Полноценный исходный редактор не подменён временным textarea; это следующий P5.2.
- Файлы открываются через ограниченные preload-методы pickOpen/loadDocument/removeDraft и [main-обработчик](../../src/platform/desktop/main/file-ipc.ts). Только main получает пути из showOpenDialog, регистрирует их и выдаёт basename/ref; ошибки отдельных путей не прерывают пачку. Renderer не получает SQL, fs, registerPath, recoverDraft или универсальный invoke/send.
- Main впервые подключает настоящую createLocalServices к production composition. Ready-reconcile предшествует операциям; разрешения привязаны к WebContents и отзываются при закрытии или новой загрузке renderer. Перед выходом прекращается приём запросов, отзывается клиент, дожидаются ready и начатые IPC-запросы, затем закрываются SQLite/сервисы.
- [Renderer-адаптер](../../src/platform/desktop/renderer/local-storage.ts) передаёт load и настоящую условную очистку черновика через IPC. Save/history/draft-put/list пока явно unsupported; нет успешных заглушек файловой записи. Dirty/неопределённый исход не закрываются молча; ошибка clearance оставляет вкладку открытой.
- Markdown-прототип сохранён как отдельный memory-only DocumentApplication. Переключение «Прототип Markdown / Документы» не уничтожает файловый workspace и не передаёт прототипу локальные ref.
- Уточнён контракт результата диалога: документы с ref/именем и отдельные ошибки пачки вместо одного списка ref. Это нужно для имён вкладок без выдачи полных путей и частичного успеха.

## 3. Исходный редактор P5.2

- [WorkspaceEditor](../../src/ui/editors/workspace-editor.ts) подключает проверенный sourceEditor к существующим файловым сессиям без новой истории текста. Выделения/IME/поиск изолированы по SessionId; при пересоздании DOM используются исходные координаты. TXT не подключает Markdown language extension, полноценный visual Markdown остаётся P6.
- [Панель редактора](../../src/ui/components/SourcePanel.tsx) предоставляет ввод, undo/redo/выделить всё и буквальный поиск/замену. [Чистая логика поиска](../../src/application/text-search.ts) отображает Unicode/CRLF-границы обратно в исходник, не нормализует NFC/NFD, поддерживает регистр, многострочный запрос и буквальный `$1`/обратный слеш в замене. Replace-all — одна прикладная транзакция и одно undo.
- Workspace получил необязательный async beforeLeave: создание/активация/открытие/закрытие ждут flush; позднее завершение диалога проверяет его повторно. При отказе flush новый открытый файл остаётся фоновой вкладкой, прежняя активная/неподтверждённый DOM не уничтожаются. Повторное намерение во время ожидания игнорируется. Завершаемая вкладка и её команды временно read-only до результата очистки.
- Dirty/неподтверждённый ввод блокирует close/quit/reload через beforeunload. Main сначала даёт окну отклонить закрытие, а только после фактического закрытия отзывает клиента/дренирует IPC/закрывает SQLite. Отзыв ref перенесён с попытки навигации на её состоявшийся commit (`did-navigate`), поэтому отменённый reload не лишает открытую сессию доступа. Это временная безопасная блокировка до полноценного P5.3, не диалог сохранения.
- Проверены отказ stale-команды после ожидания flush и смены активной сессии, включая A → B → A; поколение активации не даёт старому undo затронуть вновь активную сессию. Явный discard pending пересоздаёт только производный DOM и сохраняет актуальный подтверждённый текст.
- Итоговый `npm run check`: **220 unit-тестов в 17 файлах** (прежние 208 + 3 поиска + 6 контроллера + 3 guard-сценария workspace). [Поиск](../../tests/unit/text-search.test.ts) проверяет буквальность, Unicode/регистр/NFC/NFD и исходные CRLF/CR/LF; [контроллер](../../tests/unit/workspace-editor.test.ts) — общую историю/выделение/замены, изоляцию вкладок, ABA, pending/discard и блокировку финального закрытия.
- UI-controller unit работает в Vitest Node с тестовым EditorFactory, без jsdom/новых зависимостей; его типы проверяются renderer-конфигурацией с DOM. Node/domain-конфигурации не расширялись DOM-библиотекой. `findLastIndex` заменён совместимым с ES2022 вариантом; параллельный check/build один раз столкнулся с удалением временного Vite-конфига во время ESLint, отдельный финальный check прошёл. Последующие check и сборка запускались последовательно.
- `TMPDIR=/tmp/opencode npm run test:native`: все **152 проверки Electron**, включая семь SIGKILL, прошли повторно. Схема/зависимости/набор каналов IPC не менялись. Linux `dist:dir` прошёл; просмотр asar подтвердил отсутствие тестовых/crash-worker бандлов.
- По **37 GUI-тестов dev/packaged** прошли после последних исправлений. Output: `/tmp/opencode/neweditor-p5-editor-final-dev`, `/tmp/opencode/neweditor-p5-editor-final-packaged`. Включены все прежние Markdown/CDP-сценарии и пять новых: ввод/каретка/undo двух вкладок, Unicode/многострочный поиск и замена, IME перед tab/create/prototype, dirty-защита close/quit/reload с живой SQLite/ref и select-all/copy/cut/paste/Enter. ClipboardEvent использует локальный DataTransfer теста, не меняет пользовательский системный буфер.
- Первый полный packaged-прогон обнаружил один ввод в начале строки вместо ожидаемой восстановленной каретки. Теперь начальное выделение задаётся непосредственно в EditorState.create (без промежуточного нуля); GUI ожидает реальную позицию DOM-каретки без sleep до ввода. Сценарий повторно прошёл **по три раза** dev/packaged (`neweditor-p5-editor-caret-*`), затем весь набор 37/37 прошёл заново. Это не скрытый flaky-retry в конфигурации тестов.
- Пользовательские байты не менялись ни вводом, ни поиском/заменой. Сам рабочий текст **пока только в памяти**, что явно указано в UI. Повторный Markdown benchmark на 1 МиБ по-прежнему показывает около 1–1,6 с; он не закрывает оптимизацию P6. GUI-прогоны dev/packaged шли параллельно, это не изолированный performance-замер.
- По правилу пользователя завершённый P5.2 фиксируется отдельным коммитом с кодом/тестами/документацией; push не выполняется без отдельной просьбы. Предыдущий P5.1 — `341de78`.
- Финальная согласованность: 16 Markdown-файлов, 181 локальная ссылка, три извлечённых TypeScript-контракта компилируются; 45 уникальных задач, **27 завершены**, текущая P5.3. Fixtures неизменны, package.json/lockfile согласованы, `git diff --check` без ошибок.

## 4. Сохранение и закрытие P5.3 (2026-11-26)

- [Workspace](../../src/application/workspace.ts) подключает обычный save, Save As и проверку неизвестного/частичного исхода. Повторы команды одной сессии разделяют попытку. Диалог и повторный flush привязаны к SessionId: переход на другую вкладку не меняет адресата сохранения. Имя меняется только при подтверждённой записи; DocumentId и undo сохраняются. Новый ввод во время записи остаётся dirty относительно записанного снимка.
- [Файловый IPC](../../src/platform/desktop/main/file-ipc.ts) валидирует DTO/полномочия, канонизирует выбранную цель без регистрации, фиксирует байтовую ревизию **до** явного подтверждения замены и только затем выдаёт ref. Отмена не создаёт ресурс/файл/историю. Main-only describeResource подставляет прежний путь в системный диалог, но не выдаёт его renderer. Save/get/reconcile используют прежний журнал P4; потеря ответа даёт unknown, а не ложное not-written.
- UI предоставляет Ctrl/Cmd+S и Ctrl/Cmd+Shift+S, UTF-8/Windows-1251 и UTF-8 BOM. Метаданные — отменяемые транзакции без изменения sourceRevision. Непредставимый Unicode не заменяется и остаётся в сессии. Conflict/ошибка записи/unknown/history-pending и ошибка очистки черновика различаются; для незавершённого исхода доступно «Проверить сохранение». При конфликте пока предлагается другая цель Save As; сравнение относится к P5.4.
- Dirty-закрытие использует Save/Discard/Cancel. Discard относится к показанной stateRevision; новая правка отменяет старое разрешение. Save с отменой выбора цели/ошибкой/новыми правками оставляет вкладку. CloseAll последовательно закрывает вкладки и прекращается на отмене, не возрождая уже явно закрытые. Native close/quit проходит main→renderer handshake; SQLite остаётся доступной после отмены и закрывается только после фактического закрытия/дренирования IPC. Одобрение не обходит повторный beforeunload, dirty-reload по-прежнему блокируется.
- `npm run check`: **235 unit-тестов в 18 файлах**, типы/lint/границы/форматирование прошли. [14 новых workspace-saving сценариев](../../tests/unit/workspace-saving.test.ts) проверяют пустой файл/отмену, повторы/снимок и новый ввод, решения закрытия, отмену Save As, unknown/history-pending/reconcile, имя после неудачи, ожидание открытия и частичное closeAll; также переключение вкладки в диалоге Save As. Ещё один тест контроллера подтверждает metadata-only undo. Прежние проверки занятой другой сессией цели и отказа очистки повторены.
- `TMPDIR=/tmp/opencode npm run test:native`: **160 проверок Electron**, включая прежние семь настоящих SIGKILL. [Восемь новых save IPC](../../tests/native/file-ipc.test.ts): отмена без реестра/истории, пустая цель/идемпотентность, изменение/появление после выбора, Save As/preimage/DocumentId, чужой ref/операция/лишние DTO, codec/history-pending, закрытие после prepared и unknown после публикации без повторной записи. Новых зависимостей и миграций нет.
- `TMPDIR=/tmp/opencode npm run dist:dir` прошёл; asar содержит только runtime-каталоги out, без native-tests/crash-worker/test-бандлов. SQLite загружена из собственного asar упакованной сборки.
- По **47 GUI-тестов dev/packaged** прошли: прежние 37 + [10 новых сценариев](../../tests/electron/saving.spec.mjs). Проверены пустой/изменённый файл и повторное открытие, Save As/undo/точные CRLF/CR/LF, конфликт во время подтверждения, CP1251/UTF-8/BOM/emoji, Save/Discard/Cancel, quit нескольких вкладок, новые правки в диалоге, отменённый beforeunload с повторным close, отказ записи/успешный повтор и history-pending/reconcile без перезаписи внешнего файла. Output: `/tmp/opencode/neweditor-p5-saving-full-dev`, `/tmp/opencode/neweditor-p5-saving-full-packaged`.
- Первый targeted GUI-прогон: 20/21. В сценарии отказа записи chmod самого загруженного файла закономерно менял защищаемую ревизию и давал conflict. Тест исправлен: снимается запись с отдельного родительского каталога, исходный файл и его ревизия не меняются. После возврата прав обычный save проходит. Проверки ревизий production-кода не ослаблялись. Обновлённый targeted-набор прошёл 21/21, затем полные наборы по 47/47.
- GUI подменяет только системные dialog-функции через Playwright; history-pending воспроизводится временным SQLite trigger теста. Production test-IPC не добавлен. Проверка настоящего интерактивного системного диалога и другие ОС остаются P8. Markdown benchmark снова показывает задержку около 1,1–1,8 с на 1 МиБ; это не устранение ограничения P6 (dev/packaged шли параллельно, замер не изолирован).
- P5.3 фиксируется отдельным коммитом с кодом/тестами/документацией. Push не выполняется без просьбы пользователя. Завершены **28 из 45 задач**, текущая P5.4; весь P5 пока не завершён.
- Итоговая согласованность: 16 Markdown-файлов, 188 локальных ссылок, три извлечённых TypeScript-контракта компилируются. Fixtures неизменны, package.json/lockfile согласованы, `git diff --check` без ошибок. Повторный check после обновления документации и теста renderer-переадресации также прошёл.

## 5. Внешние изменения P5.4 (2026-11-26)

- [Координатор наблюдения](../../src/application/workspace-observation.ts) ведёт одну подписку на location сессии, отзывает её при Save As/закрытии/dispose, объединяет сигналы и перед чтением вызывает flush соответствующей SessionId. Watch/error старой подписки не затрагивают новую цель. Событие во время save/unknown/history-pending ждёт известного исхода; workspace явно удерживает saving-флаг и на reconcile до его завершения.
- [IPC](../../src/platform/desktop/main/file-ipc.ts) добавляет resource:watch/unwatch/refresh и resource:notification, [preload](../../src/platform/desktop/preload/index.ts) предоставляет фиксированные watchResource/refreshResources без универсального invoke. UUID подписки выбирается preload до запроса, listener устанавливается до invoke: это сознательное уточнение server-generated ID ранней схемы, чтобы не терять раннее событие и немедленную отписку. ID не заменяет проверку выданного ref; map принадлежит конкретному клиенту окна. Main отзывает pending/active watch при закрытии/reload, focus запускает refresh с учётом операции при shutdown.
- [DocumentApplication.reload](../../src/application/document-application.ts) сохраняет dirty-текст/undo и старую expectedRevision, отдавая внешний снимок только в conflict.observed. Чистая сессия обновляет baseline/ревизию/DOM и очищает undo старого текста. Проверки stateRevision/readSequence/saveGeneration сохраняются; stale-read после нового ввода повторяется координатором. Ошибка чтения/декодирования оставляет текст и changed без снимка (либо deleted), не подставляет пустой файл. Успешный reload снимает прежний failed-save.
- [UI сравнения](../../src/ui/components/Workspace.tsx) — две безопасные read-only панели исходного текста с кодировкой/BOM; HTML не исполняется, merge/diff-библиотека не добавлялась. Можно продолжить редактировать рабочую копию, сохранить её через Save As в другую цель или явно загрузить внешний файл. Последнее действие повторяет flush/load и проверяет **обе показанные ревизии** через новый optional expected-параметр reload. Изменение рабочего текста или внешнего снимка отменяет старый discard; очистка undo выполняется только при успешном принятии.
- Удаление не теряет даже чистую копию: текст остаётся в редакторе, доступен Save As. Любой conflict требует Save/Discard/Cancel при закрытии; Save из такого вопроса выбирает Save As. Даже чистый deleted/conflict блокирует reload renderer. Появление файла снова приводит к обычному сравнению или чистому перечитыванию. «Проверить изменения» повторяет чтение всех сессий после ошибки/пропущенного сигнала.
- `npm run check`: **250 unit-тестов в 19 файлах**, типы/lint/границы/форматирование прошли.
