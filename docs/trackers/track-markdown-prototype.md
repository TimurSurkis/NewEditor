# Проверочный прототип Markdown P3

Начало: 2026-11-24. Итоговые проверки: 2026-11-25.
Статус: **P3 завершён на Linux x64; ограничения производительности и системного IME остаются открытыми для P6/P8**.
Основания: [спецификация](../specifications/spec-markdown-editing.md), [fixtures](../specifications/fixtures/spec-markdown-cases.json), [план](plan-desktop-v1.md).

## Принятое решение

Связку **CodeMirror 6 + ProseMirror** сохраняем. Исходный Markdown остаётся единственным содержимым application-сессии. Visual отображает дерево, а его поддерживаемые действия превращаются в ограниченные исходные замены. Полного PM → Markdown сериализатора нет. Неоднозначные и неподдерживаемые фрагменты защищены и доступны в source.

Код:

- [Формат и команды](../../src/formats/markdown/markdown.ts), [карта текстовых координат](../../src/formats/markdown/source-map.ts).
- [CodeMirror](../../src/ui/editors/source-editor.ts), [визуальная проекция](../../src/ui/editors/visual-projection.ts), [ProseMirror](../../src/ui/editors/visual-editor.ts).
- [Контроллер общей сессии](../../src/ui/editors/prototype-controller.ts), [IME/flush](../../src/ui/editors/composition.ts).
- [Интерфейс стенда](../../src/ui/components/MarkdownPrototype.tsx), [адаптер в памяти](../../src/platform/memory/index.ts). Старый импорт tests/support оставлен как re-export для контрактных тестов.

Из каркаса доступна кнопка **«Прототип Markdown»**. Стенд не открывает файлы, не сохраняет документ на диск и не создаёт SQLite-версии. Загрузку точных CRLF/CR позволяет режим JSON-строки; точный исходник также отображается JSON-строкой. Это диагностика стенда, не формат документа. Проверка снимка ждёт flush, но не имитирует успешную запись файла.

## Версии и среда

Прямые зависимости фиксированы: CodeMirror state 6.7.6, view 6.43.15, commands 6.11.1, lang-markdown 6.5.2; ProseMirror model 1.25.13, state 1.4.4, view 1.44.0; unified 11.0.5, remark-parse 11.0.0, remark-gfm 4.0.1, micromark-util-decode-string 2.0.1. Типы mdast 4.0.4. Полный граф — в package-lock.json.

Проверяемая ОС: Linux x64, kernel 7.0.0-43-generic, DISPLAY `:0`; AMD Ryzen 5 PRO 5650U (12 логических CPU), 30 ГиБ памяти по os.totalmem. Node инструментов 24.11.1, Electron 45.4.1 / Node 24.22.3 / ABI 150. Цифры производительности зависят от нагрузки машины и не заменяют проверки остальных ОС.

## Проверенные свойства

- **MD-01–MD-12:** все 12 точных примеров прошли в настоящем DOM Electron: переключения, inline-формат, вложенные checkbox, ячейка таблицы, неизвестный HTML/директива, fenced code с CRLF, reference-ссылка, emoji/NFD, нумерация `7)`/`9)`, alt изображения и heading с закрывающими маркерами. Изменяющие случаи дополнены source → undo → visual → redo; expected используется только для сравнения результата, не для выдачи правки.
- **ME-01:** счётчик host.dispatch и ревизии не растут от переключений и программного metadata-only кадра; цикла обновлений нет.
- **ME-02:** старая композиция обоих движков после внешней правки отклоняется; новая модель сохраняется, неподтверждённый текст остаётся видимым/доступным для копирования. Flush и смена режима блокируются до явного отбрасывания.
- **ME-03:** metadata-only кадр принимается без изменения исходника и замены PM DOM; дерево переиспользуется только при совпадении sourceRevision **и** текста. Свежий ввод использует новую stateRevision.
- **ME-04–ME-05:** Chromium CDP выполняет несколько промежуточных IME-состояний; в модель поступает одна завершённая композиция. Быстрые отдельные композиции отменяются отдельно. Снимок и смена режима ждут compositionend/flush. Это проверка интеграции через Chromium, не ручная проверка системного IME всех ОС.
- **ME-06:** исходное выделение внутри скрытого URL, возле emoji и CRLF переживает переключения; защищённый HTML можно открыть в source. HTML не становится исполняемым DOM.
- **ME-07–ME-08:** новый блок рядом с защищённым HTML сохраняет его исходник; source/visual-правки отменяются в общей последовательности, включая горячие клавиши.
- **ME-09:** 10 КБ, 100 КБ и 1 МБ проверены на разбор, создание visual, ввод и undo без потери текста; есть существенное ограничение задержки на 1 МБ (ниже).

Наборы: [unit](../../tests/unit/markdown-format.test.ts), [Electron](../../tests/electron/markdown.spec.mjs). В дополнение сохраняются P1/P2-тесты и 3000 детерминированных наборов ядра.

На 2026-11-25 прошли чистая установка `npm ci`, `npm run check` (106 unit-тестов в 6 файлах, domain/main/renderer-типы, lint, границы и форматирование), 4 native-проверки SQLite и `npm run dist:dir`. Все **27 GUI-тестов прошли и в dev, и в упакованном Linux-приложении** (25 сценариев прототипа и 2 регрессии каркаса), включая собственный native-модуль в asar и отсутствие предупреждений некорректного выделения.

Production npm-аудит — 0 уязвимостей; прежние 6 moderate-позиций инструментов сборки остаются ограничением из отчёта P1. Сообщение electron-builder о повторных ссылках графа зависимостей не является ошибкой упаковки: запакованный runtime проверен настоящим Electron.

## Найденные и исправленные проблемы

1. HTML textarea нормализовал CRLF ещё при подготовке стенда: точная загрузка/наблюдение переведены на JSON-строку. Сам документ остаётся обычным исходным текстом.
2. Нативная замена выделенного кода могла дать промежуточное удаление до вставки: обычный insertText перехвачен на beforeinput, до мутации DOM. IME оставлен отдельным жизненным циклом.
3. Граница соседних inline-листьев могла превращать визуальный caret в выделение скрытого маркера: для пустого выделения используется одинаковая привязка anchor/head.
4. Пересечение общих префикса/суффикса при diff повторяющихся букв и быстрые compositionend/start потребовали отдельной обработки; добавлены проверки отдельных undo-групп.
5. Нормализация Shift+Ctrl+z в библиотечном keymap могла вызвать undo вместо redo: история перехватывается по модификаторам до keymap движка, обе команды идут в application.
6. Повторный разбор одной ревизии контроллером и visual устранён через проверяемый EditorFrame.markdown. Полный разбор каждой **новой** ревизии пока остаётся.
7. CodeMirror создаёт CSS и геометрию во время работы: production CSP разрешает inline-стили, но не inline-скрипты. HTML документа остаётся текстом; сеть/frame/произвольная навигация и Node renderer запрещены.
8. Защищённый атом нельзя выбирать текстовым курсором ProseMirror на уровне doc. Используется NodeSelection; обработка мыши защищённого фрагмента выполняется до стандартного поиска слова библиотекой. Добавлены проверки отсутствия предупреждения TextSelection endpoint и возврата точного исходного выделения из HTML.

## Производительность и ограничения

Данные ME-09: ASCII-документ точного размера с повторяемыми heading, абзацами, strong и ссылками. Разбор — unified/remark в контроллере; создание visual — ProseMirror вместе с картой и DOM из уже разобранной ревизии; создание source — CodeMirror с картой переводов строк. Ввод измерен до наблюдения обновлённого исходника, включая UI и обмен с тестовым драйвером, а не как чистое время applyTransaction. Каждый ввод проверен последующим undo до точного исходника.

Один итоговый прогон **packaged Linux**, мс (не медиана и не гарантия):

| UTF-8 размер | Разбор | Создание visual | Ввод visual | Создание source | Ввод source |
| --- | ---: | ---: | ---: | ---: | ---: |
| 10 240 байт | 33,9 | 13,7 | 45 | 4,9 | 48 |
| 102 400 байт | 155,5 | 76,3 | 237 | 13,6 | 225 |
| 1 048 576 байт | 1152,0 | 105,3 | 1048 | 51,0 | 1092 |

Контрольный dev-прогон на тех же размерах (мс): разбор 48,7 / 225,1 / 1704,5; ввод visual 57 / 334 / 1364; ввод source 56 / 286 / 1456. Артефакт измерений прикрепляется Playwright как `markdown-benchmark.json`; он не является частью исходного документа.

Повторные запуски дают разброс в зависимости от нагрузки; dev заметно медленнее. Правки и undo не теряются, но задержку около секунды на 1 МБ нельзя считать приемлемой отзывчивостью готового редактора. До завершения P6 нужны оптимизация разбора/проекции (в том числе лишней работы в source) и повторные замеры; P8 проверяет итоговую отзывчивость. Предел размера продукта этим не вводится.

Другие открытые границы:

- Структурные split/join списка/таблицы, неоднозначные или неподдерживаемые PM-транзакции не сериализуются автоматически. Они требуют source/расширения P6; неподтверждённый ввод не заменяет канонический текст.
- Неоднозначные текстовые отображения, indented code и смешанный inline HTML защищены консервативно. Полный набор GFM-команд, диалоги и работа с физическими изображениями — P6. Ссылки не навигируют, внешние изображения не загружаются, вместо них безопасная метка.
- IME систем Windows/macOS и ручные сценарии разных раскладок пока не проверены. Строки платформенной матрицы остаются открытыми; CDP не обозначается проверкой реального системного IME.
- Файловое сохранение, внешние изменения реального файла, история и восстановление после перезапуска не входят в стенд. Следующий этап — P4, не выпуск готового редактора.
