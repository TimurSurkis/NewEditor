# Документное ядро и сессии P2

Дата: 2026-11-24.
Статус: **P2 завершён**.
Основания: [модель документа](../specifications/spec-document-model.md), [контракты](../specifications/spec-module-contracts.md), [план](plan-desktop-v1.md).

## Результат

- [Core](../../src/core/index.ts): типы документа/снимков/правок; создание пустого состояния; точное сравнение; Unicode/CRLF-границы; атомарные транзакции и канонический inverse; undo/redo до 200 групп.
- [Application](../../src/application/index.ts): создание/открытие/закрытие сессий, стабильные frozen-снимки и подписки, выделение и границы групп, сохранение конкретного снимка, объединение следующих намерений, unknown/history-pending/reconcile, условная очистка черновиков и безопасное перечитывание.
- [Ports](../../src/ports/index.ts): типы хранения, истории, черновиков, вложений, наблюдений и будущего доступа. Облачная реализация не добавлена.
- [Тестовое хранилище](../../tests/support/memory-store.ts): ресурсы в памяти, проверка expectedRevision, идемпотентные operationId, пять версий, монотонные черновики и границы очистки. Это тестовый адаптер, не файловое хранилище и не механизм восстановления после перезапуска.
- `tsconfig.domain.json` отдельно проверяет core/ports/formats/application с `lib: ES2022`, без ambient-типов Node, Electron или DOM. Зависимости не добавлены, lockfile не изменён.

## Существенные уточнения контрактов

1. Undo удаления `X` из `\rX\n` не вставляет внутрь образовавшегося CRLF, а заменяет его целым диапазоном. Иначе собственный inverse нарушал бы валидацию модели.
2. Переполнение безопасной ревизии — атомарная ошибка `revision-overflow`; счётчики не теряют точность.
3. `setSelection`/`breakUndoGroup` задают границы пользовательских действий без правки текста. Командный groupId сам по себе не разрешает склеивать произвольные правки: для ввода проверяются одна замена вокруг выделения, смежность и интервал 0–500 мс.
4. Ошибка очистки черновика доступна в `SessionView.draftError` и не отменяет подтверждённую запись файла. Закрытие при ошибке очистки не происходит.
5. Ожидающая запись в ту же цель использует подтверждённую ревизию собственной предыдущей записи, если её target содержал именно прежнюю ревизию этой операции. Внешние изменения по-прежнему проверяет адаптер.
6. Конфликт другой цели «Сохранить как» возвращается вызывающей команде, не создавая ложный внешний конфликт исходного ресурса.

Эти решения внесены в спецификации до соответствующей реализации. Сохранение/переключение реального редактора требует flush IME в UI; оно не подменяется проверкой доменной транзакции.

## Проверки

`npm run check` прошёл: самостоятельные типы domain/main/renderer, ESLint, AST-границы импортов, Prettier и **83 unit-теста в 5 файлах** (70 новых относительно P1). В одном тесте дополнительно выполнены **3000 детерминированных наборов** многодиапазонных правок с Unicode и смешанными переводами строк: результат сравнивается с прямой заменой, inverse восстанавливает точный исходник.

## Оставшиеся границы

- UI по-прежнему показывает каркас: ядро ещё не подключено к настоящим редакторам. Следующий этап — P3, затем файловый адаптер P4 и пользовательские сценарии P5/P6.
- В P2 нет таймеров авточерновиков, восстановления сессии, файлового наблюдателя, диалогов, реального файлового журнала или облачной аренды. Их поведение не считается доказанным тестовым хранилищем.
- Локальная половина общей контрактной проверки MC-01 и реальные частичные сбои сохранения остаются для P4; в P2 проверены память и управляемые ответы/задержки портов.
- Семантика идентичности «Сохранить как» и первой версии существующего файла окончательно уточняется в P4. P2 сохраняет ID рабочей модели при смене цели.
- Проверки выполнены на Linux x64; матрица Windows/macOS остаётся без новых отметок.
