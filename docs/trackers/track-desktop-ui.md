# Десктопный интерфейс P5: прогресс и проверки

Начало: 2026-11-25.
Статус: **P5.1 завершён на Linux x64; текущая задача P5.2**.
Основания: [спецификация UI](../specifications/spec-desktop-ui.md), [план](plan-desktop-v1.md), [контракты](../specifications/spec-module-contracts.md), [результаты P4](track-local-persistence.md).

## 1. Результат P5.1

- [WorkspaceApplication](../../src/application/workspace.ts) управляет вкладками поверх DocumentApplication: монотонные имена новых TXT/MD, порядок/активная вкладка, частичные ошибки открытия, активация прежнего ref без дубликата, выбор соседа после закрытия, dirty/closing-индикаторы и очистка подписок. Текст и ревизии не дублируются: вкладка ссылается на неизменяемый SessionView.
- [UI вкладок](../../src/ui/components/Workspace.tsx) предоставляет создание TXT/Markdown, открытие, переключение мышью/стрелками/Home/End и отдельные кнопки закрытия. Исходник показывается **только для чтения** в pre как текст, включая CRLF/CR/NFC/NFD. Полноценный исходный редактор не подменён временным textarea; это следующий P5.2.
- Файлы открываются через ограниченные preload-методы pickOpen/loadDocument/removeDraft и [main-обработчик](../../src/platform/desktop/main/file-ipc.ts). Только main получает пути из showOpenDialog, регистрирует их и выдаёт basename/ref; ошибки отдельных путей не прерывают пачку. Renderer не получает SQL, fs, registerPath, recoverDraft или универсальный invoke/send.
- Main впервые подключает настоящую createLocalServices к production composition. Ready-reconcile предшествует операциям; разрешения привязаны к WebContents и отзываются при закрытии или новой загрузке renderer. Перед выходом прекращается приём запросов, отзывается клиент, дожидаются ready и начатые IPC-запросы, затем закрываются SQLite/сервисы.
- [Renderer-адаптер](../../src/platform/desktop/renderer/local-storage.ts) передаёт load и настоящую условную очистку черновика через IPC. Save/history/draft-put/list пока явно unsupported; нет успешных заглушек файловой записи. Dirty/неопределённый исход не закрываются молча; ошибка clearance оставляет вкладку открытой.
- Markdown-прототип сохранён как отдельный memory-only DocumentApplication. Переключение «Прототип Markdown / Документы» не уничтожает файловый workspace и не передаёт прототипу локальные ref.
- Уточнён контракт результата диалога: документы с ref/именем и отдельные ошибки пачки вместо одного списка ref. Это нужно для имён вкладок без выдачи полных путей и частичного успеха.

## 2. Выполненные проверки

- `npm run check`: **208 unit-тестов в 15 файлах**, типы domain/main/renderer, lint/границы/форматирование прошли. Новые 7 проверок workspace, 1 renderer-адаптера и 1 общей проверки main-frame дополняют прежние 199.
- [Workspace unit](../../tests/unit/workspace.test.ts) проверяет имена/активацию/соседей, отмену/единственный диалог, дубликаты и частичный отказ, dirty/ошибку clearance, отписки/dispose, исключение слушателя и синхронную новую правку на уведомлении closing. Такая правка оставляет вкладку открытой, а не попадает под discard.
- `TMPDIR=/tmp/opencode npm run test:native`: **152 проверки в runtime Electron** — прежние 146 + [6 проверок file IPC](../../tests/native/file-ipc.test.ts). Проверены отмена без реестра, частичный успех/basename/точное чтение/исходная история, невыданный ref/extra/path/нецелая clearance, объединение диалога, отзыв клиента до ответа/во время чтения и реальная owner-ограниченная очистка void→null. Все прежние семь SIGKILL прошли повторно.
- `TMPDIR=/tmp/opencode npm run dist:dir`: сборка/упаковка Linux прошли. Просмотр app.asar подтвердил runtime-каталоги и отсутствие native/crash-worker/test-бандлов. Нативная SQLite загружена из зависимостей собственного asar, не из внешнего node_modules.
- По **32 GUI-теста dev/packaged** прошли: прежние 27 каркаса/Markdown + [5 новых сценариев workspace](../../tests/electron/workspace.spec.mjs). Output: `/tmp/opencode/neweditor-p5-workspace-full-dev`, `/tmp/opencode/neweditor-p5-workspace-full-packaged`.
- После последнего ограничения createWindow при начатом shutdown повторены check/упаковка/просмотр asar и по 7 GUI-проверок каркаса/workspace dev/packaged; всё прошло. Output: `/tmp/opencode/neweditor-p5-workspace-final-dev`, `/tmp/opencode/neweditor-p5-workspace-final-packaged`.
- Новые GUI-сценарии проверяют создание/закрытие/переключение и возврат из прототипа; UTF-8/CP1251/Markdown с точным textContent и неизменными пользовательскими байтами; неисполняемый HTML; отмену и частичные ошибки; настоящий IPC с невыданным ref/чужим WebContents/extra-полями; отзыв ref при reload; штатный выход, дожидающийся незавершённого диалога. Subframe-флаг общей границы проверен unit-набором; новый отдельный subframe-IPC-эксперимент в GUI не заявляется.
- GUI подменяет только Electron dialog-функцию в main через Playwright для выбора/отмены. Production test-IPC/полей пути/переменных тестового разрешения нет. Ручное взаимодействие с системным диалогом и остальные ОС остаются P8.
- Ошибки первичных прогонов были в тестовой обвязке: ESLint потребовал явный импорт Buffer/обращение к timers через process в сериализуемом main-callback; повтор Prettier выровнял тест workspace. Финальный check прошёл, поведенческих падений нативного/GUI-набора не было.
- Согласованность документации: 16 Markdown-файлов, 175 локальных ссылок, три извлечённых TypeScript-контракта компилируются; 45 уникальных задач, **26 завершены**, текущая P5.2. Fixtures неизменны, package.json/lockfile согласованы, `git diff --check` без ошибок. Новых зависимостей/миграций не добавлено.

## 3. Открытые ограничения и следующий шаг

- **P5.2:** сначала уточнить spec-desktop-ui.md для исходного редактора, flush/IME при переключении/закрытии, выделений и поиска/замены; затем подключить CodeMirror к файловым сессиям. Сейчас вкладки только читают текст, dirty-индикатор проверен через прикладную транзакцию в unit, не через файловый ввод GUI.
- **P5.3:** сохранение/Save As/кодировка/BOM и решение о несохранённых изменениях при закрытии. До этого UI не создаёт несохранённого текстового ввода и не экспортирует файловую запись. Текущий shutdown не считается готовым протоколом закрытия dirty-редактора.
- **P5.4:** ресурсные подписки IPC, focus-refresh, чистое перечитывание/сравнение и удаление файла. Часть LP-13, относящаяся к subscriptionId, всё ещё открыта; базовые runtime-полномочия load уже проверены.
- Открытие файлов сейчас через диалог; аргументы запуска, ассоциации и передача путей второго запуска ещё не подключены, их проверка должна войти в сквозную приёмку P5.5/P8.
- История/авточерновики/восстановление UI — P7. Markdown визуальный режим/изображения — P6; прежняя задержка ввода на 1 МиБ остаётся открытой, повторный benchmark этого шага не является оптимизацией.
- Windows/macOS и системный IME не проверены. Результаты Linux и Chromium/CDP не закрывают матрицу остальных ОС.
- По новому указанию пользователя завершённый P5.1 фиксируется отдельным коммитом. Далее каждый завершённый пункт плана коммитится вместе с тестами/документацией; push — только по отдельной просьбе.
