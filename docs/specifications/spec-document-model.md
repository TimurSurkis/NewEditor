# Спецификация модели документа

Статус: **контракт P0.1 реализован в доменном ядре P2; интеграция редакторов — P3**.
Редакция: 2026-11-24.
Основание: [концепция](../concepts/concept-project.md), [архитектура](spec-architecture.md).
Связанные документы: [контракты модулей](spec-module-contracts.md), [редактирование Markdown](spec-markdown-editing.md).

## 1. Инварианты

- Основное содержимое — исходный TXT/Markdown. Визуальная структура и состояния сторонних редакторов производны от него.
- Текст в памяти сохраняет исходные переводы строк, пробелы и завершающий перевод строки. Загрузка и переключение режимов не нормализуют его.
- Правка применяется атомарно к известному состоянию. Ошибка оставляет текст, метаданные, ревизии и стек отмены прежними.
- Нетронутые фрагменты Markdown и неподдерживаемая разметка сохраняются.
- Сохранённое состояние, рабочая сессия, авточерновик и запись истории — разные сущности.
- Пять версий истории включают последнее сохранённое состояние; авточерновики в лимит не входят.

## 2. Типы ядра

Блок задаёт публичные типы `core`. Идентификаторы — непрозрачные непустые строки; генерацию обеспечивает приложение. Ревизии — неотрицательные безопасные целые числа, начиная с нуля. Реализация и проверки: [отчёт P2](../trackers/track-document-core.md).

```ts
export type DocumentId = string;
export type SessionId = string;
export type OperationId = string;
export type StorageRevision = string;
export type Revision = number;
export type DocumentFormat = 'txt' | 'markdown';

export interface StorageRef {
  readonly storageId: string;
  readonly resourceId: string;
}

export interface FileMetadata {
  readonly encoding: 'utf-8' | 'windows-1251';
  readonly bom: boolean;
}

export interface DocumentSnapshot {
  readonly text: string;
  readonly fileMetadata: FileMetadata;
}

export interface Document extends DocumentSnapshot {
  readonly id: DocumentId;
  readonly format: DocumentFormat;
  readonly location: StorageRef | null;
  readonly sourceRevision: Revision;
}

export interface EditState {
  readonly document: Document;
  readonly stateRevision: Revision;
}

export interface SourceSelection {
  readonly anchor: number;
  readonly head: number;
}

export interface TextChange {
  readonly from: number;
  readonly to: number;
  readonly insert: string;
}

export interface TransactionBody {
  readonly changes: readonly TextChange[];
  readonly fileMetadata?: FileMetadata;
}

export interface EditTransaction {
  readonly documentId: DocumentId;
  readonly baseStateRevision: Revision;
  readonly body: TransactionBody;
  readonly selectionBefore: SourceSelection;
  readonly selectionAfter: SourceSelection;
  readonly groupId: string | null;
}

export interface ModelError {
  readonly code: 'wrong-document' | 'stale-revision' | 'invalid-range'
    | 'invalid-text' | 'invalid-metadata' | 'invalid-selection' | 'revision-overflow';
  readonly message: string;
}

export type Result<T, E> =
  | { readonly ok: true; readonly value: T }
  | { readonly ok: false; readonly error: E };

export interface AppliedTransaction {
  readonly state: EditState;
  readonly changed: boolean;
  readonly inverse: TransactionBody | null;
  readonly selection: SourceSelection;
}

export declare function applyTransaction(
  state: EditState,
  transaction: EditTransaction,
): Result<AppliedTransaction, ModelError>;

export declare function equalSnapshots(
  a: DocumentSnapshot,
  b: DocumentSnapshot,
): boolean;
```

### 2.1. Представление текста и метаданные

`text` — корректная Unicode-строка без непарных UTF-16-суррогатов. Никакой Unicode-нормализации NFC/NFD при применении правок нет. BOM файла вынесен в метаданные; обычные символы U+FEFF внутри содержимого остаются текстом.

`bom: true` допустим только при `encoding: 'utf-8'`. Новый документ: пустой текст, UTF-8 без BOM, `location: null`, обе ревизии равны нулю.

Переводы строк представлены непосредственно в `text`, включая смешанные LF/CRLF/CR. Для вставки нового перевода строки используется наиболее частый вид в документе; при равенстве — первый встреченный, при отсутствии — LF. Интеграция редактора сопоставляет нормализованные координаты своего движка с исходным текстом.

Изменение кодировки выполняется отдельной транзакцией метаданных. Проверка представимости символов в Windows-1251 происходит перед записью в адаптере: непредставимый текст возвращает ошибку кодирования, без подстановки `?` и без изменения файла.

### 2.2. Идентичность и ревизии

- `Document.id` связывает рабочий документ с его данными. При переключении режимов и редактировании он не меняется.
- `SessionId` уникален для каждого открытия/восстановления сессии. Ответ от закрытой сессии не применяется к новой, даже если `Document.id` совпал.
- `sourceRevision` увеличивается только при фактическом изменении текста; используется для разбора Markdown и текстовых координат.
- `stateRevision` увеличивается при изменении текста **или** метаданных сохраняемого снимка. Используется для транзакций, снимков сохранения и порядка авточерновиков.
- Подтверждение сохранения, изменение курсора и переключение режима не увеличивают эти ревизии.
- Ревизия хранилища выдаётся адаптером и сравнивается только на равенство. Номер версии истории не заменяет ни одну из этих ревизий.

Две ревизии нужны, чтобы изменение кодировки при неизменном тексте не потерялось при фоновой записи. Работа с путями и идентичностью после «Сохранить как» детализируется в P4; ядро работает с `StorageRef`.

## 3. Транзакция правок

### 3.1. Координаты и валидация

Диапазоны `[from, to)` задаются в UTF-16-индексах исходного текста до транзакции. `selectionBefore` относится к исходному тексту, `selectionAfter` — к результату.

Проверки в указанном порядке:

1. Совпадают `documentId` и `baseStateRevision` с текущим состоянием.
2. Координаты целые, находятся в границах текста, `from <= to`.
3. Изменения упорядочены по `from`. Одинаковые начала и пересечения запрещены; вызывающая сторона объединяет неоднозначные изменения заранее.
4. Ни одна граница не проходит внутри суррогатной пары или между CR и LF одного перевода строки. Аналогичные ограничения действуют для выделения.
5. Вставляемые строки корректны; метаданные проходят проверку совместимости encoding/BOM.
6. Вычисленный результат и `selectionAfter` корректны.

Границы графем, например составной emoji или буквы с комбинируемым знаком, учитывает редактор при пользовательском перемещении курсора. Ядро гарантирует целостность кодовых точек и CRLF.

### 3.2. Применение

Правки вычисляются по одному исходному состоянию и применяются справа налево. Касающиеся диапазоны допустимы при разных началах. Обратные изменения канонизируются: касающиеся диапазоны и совпадающие начала объединяются с сохранением порядка исходного текста. Возвращённая обратная операция должна проходить ту же валидацию, включая случай нескольких соседних удалений.

Уточнение P2 (2026-11-24): если удаление соединяет отдельные CR и LF в CRLF, обратный диапазон расширяется до целого CRLF с сохранением символов. Например, undo удаления `X` из `\rX\n` заменяет весь `\r\n` на `\rX\n`, а не вставляет внутрь запрещённой границы. Переполнение безопасного счётчика возвращает `revision-overflow` атомарно. Состояния и публичные снимки копируются и глубоко замораживаются: изменения входного DTO или полученного снимка не меняют сессию.

После успешной проверки:

- Если итоговый снимок отличается, `stateRevision` увеличивается на один; `sourceRevision` увеличивается на один, только если изменился текст.
- Возвращается обратная операция относительно нового текста и прежние метаданные, если они менялись.
- Если итоговый снимок совпал с исходным, возвращается `changed: false`, `inverse: null`; ревизии и история отмены не меняются. Выделение может обновиться.
- Входные объекты не изменяются; результат представляет новое неизменяемое состояние.

Устаревшая транзакция возвращает `stale-revision`. Она не переносится автоматически на другие координаты. Интеграция получает актуальный снимок и заново вычисляет действие, сохраняя незавершённый пользовательский ввод до успешного применения.

Пример: в строке `A😀Б\r\n` emoji занимает `[1, 3)`. Замена `[1, 3)` допустима, `[2, 3)` — нет. Позиция между `\r` и `\n` также недопустима.

## 4. Undo/redo

Сессия хранит группы прямых и обратных транзакций с выделениями до и после. История редакторских библиотек направляет команды в эту сессию.

- Одна команда форматирования, замены или IME-композиция — одна группа.
- Последовательный обычный ввод может объединяться в группу при смежных позициях и интервале до 500 мс. Командный слой задаёт непустой `groupId`; `application` проверяет одинаковый ID, смежность выделений и интервал по внедрённым часам. Ядро не читает часы. Для отдельных команд используется `groupId: null`; IME передаётся одной транзакцией.
- Перемещение выделения, переключение режима, начало сохранения и команда форматирования завершают текущую группу.
- Группа undo применяется в обратном порядке к временной копии, redo — в прямом. Группа фиксируется атомарно; ревизии увеличиваются один раз по правилам изменения снимка.
- Новая фактическая правка после undo очищает redo. Пустая операция его не очищает.
- Undo/redo без доступной группы — успешная операция без изменения состояния.
- Для первой версии удерживаются последние 200 групп на документ; наиболее старые группы удаляются первыми.
- Сохранение не очищает undo. При загрузке внешнего состояния или восстановлении сессии после перезапуска стек начинается заново. Восстановление исторического снимка внутри текущей сессии — одна отменяемая транзакция.

Undo/redo используют текущую ревизию, а не старую ревизию исходной команды. Возврат к прежнему тексту получает новую ревизию.

## 5. Сессия и несохранённые изменения

Сценарии приложения владеют сессией: `EditState`, `SessionId`, базовым снимком, ревизией хранилища, состоянием сохранения/конфликта и undo/redo. Вкладка владеет режимом, выделением и прокруткой.

`isDirty = !equalSnapshots(currentSnapshot, baselineSnapshot)`. Сравнение учитывает точный текст, encoding и BOM. У нового документа базой служит начальный пустой снимок; `isNew` определяется отсутствием `location` независимо от `isDirty`. Первый вызов сохранения нового пустого документа создаёт файл.

Открытый существующий файл изначально чистый. Отмена правок до базового снимка снимает `isDirty`, даже если номера ревизий выросли. Авточерновик базу не изменяет.

## 6. Сохранение и конкурентные операции

Сценарий фиксирует `SessionId`, `operationId`, `stateRevision`, неизменяемый снимок, целевой ресурс и ожидаемую ревизию хранилища. Одновременно выполняется одно сохранение сессии. Повторное нажатие сохранения ставит не более одного следующего намерения; его снимок создаётся при фактическом старте.

| Результат | Изменение сессии |
| --- | --- |
| Успех | База, location и ревизия хранилища обновляются подтверждённым снимком; текущий текст остаётся на месте |
| Файл записан, история ожидает фиксации | База обновляется; состояние `history-pending` сохраняет операцию для восстановления |
| Запись не выполнена | База прежняя; рабочие правки сохранены, ошибка доступна UI |
| Конфликт ревизии | База прежняя; конфликт доступен для сравнения, автоматической перезаписи нет |
| Результат неизвестен из-за потери ответа | Состояние `unknown`; база не меняется до выяснения результата по `operationId` |

Ответ применяется только к ожидаемой операции и живой сессии. Закрытие сессии не отменяет запись, уже принятую main; её результат остаётся в сервисе сохранения и журнале. Снимок подтверждения никогда не заменяет текущий рабочий текст.

Новые сохранения ждут завершения состояний `history-pending` и `unknown`. Повтор для выяснения результата использует тот же `operationId`; новый снимок получает новый ID.

Черновик содержит `SessionId` и `stateRevision`. Удаление подтверждённого черновика условно: очищаются только ревизии до записанного снимка включительно. Хранилище помнит границу очистки, чтобы запоздавшая запись старого черновика не восстановила уже очищенные данные.

## 7. Внешние изменения и закрытие

При сигнале об изменении файла приложение перечитывает ресурс и запоминает текущие `SessionId`, `stateRevision` и номер запроса наблюдения. Результат применяется автоматически только если запрос всё ещё последний, сессия чистая, её состояние не изменилось и нет незавершённого сохранения/IME-композиции.

- Чистый документ: обновляются рабочий и базовый снимки, ревизия хранилища; undo/redo очищаются. Ревизии рабочего состояния увеличиваются по фактическому изменению снимка.
- Документ с правками: рабочий текст сохраняется, внешний снимок доступен для сравнения.
- Удалённый файл: рабочий текст сохраняется; ресурс отмечен отсутствующим, доступны сохранение в новое место или явное восстановление файла.
- Сигнал собственной записи перепроверяется после подтверждения сохранения; равная ревизия не создаёт ложного конфликта.

При закрытии изменённого документа UI предлагает сохранить, отбросить изменения или отменить закрытие. Сохранить означает дождаться известного завершения операции и проверить, что текущий снимок совпадает с подтверждённым и нет конфликта. Новые правки во время ожидания оставляют сессию открытой. Отбрасывание очищает черновик только этой сессии; ошибка очистки не закрывает её. На время окончательной очистки и закрытия новые изменения блокируются. При `saving`, `unknown` или `history-pending` обычное закрытие откладывается до разрешения операции; аварийное завершение обслуживает механизм восстановления.

## 8. Критерии приёмки P2

| ID | Проверка и ожидаемый результат |
| --- | --- |
| DM-01 | Открытие сохраняет точный текст и даёт чистую сессию; новый пустой документ сохраняется несмотря на `isDirty: false` |
| DM-02 | Правка → undo до базы снимает dirty; ревизии не уменьшаются |
| DM-03 | Смена encoding при прежнем тексте меняет только `stateRevision` и dirty |
| DM-04 | Устаревшая ревизия, пересечение диапазонов, непарный суррогат и разрыв CRLF отклоняются атомарно |
| DM-05 | Несколько замен и обратная операция восстанавливают точный исходник, включая соседние удаления |
| DM-06 | Пустая операция не меняет ревизии, undo и redo |
| DM-07 | Группа ввода/IME отменяется целиком; переключение режима не создаёт правку |
| DM-08 | Сохранение A при последующем вводе B подтверждает A, оставляя B и корректный dirty |
| DM-09 | Metadata-only правка во время сохранения не теряется; условная очистка черновика учитывает stateRevision |
| DM-10 | Ошибка, частичный успех и неизвестный результат приводят к разным состояниям; повтор операции не создаёт новую версию |
| DM-11 | Запоздавший ответ закрытой сессии не меняет повторно открытый документ |
| DM-12 | Внешнее чтение, начатое до новой правки, не перезаписывает эту правку |

Схема SQLite и конкретные файловые операции зафиксированы в [спецификации P4](spec-local-persistence.md); отображение ошибок — P5. Контракты модели и её поведение для P1–P3 определены этим документом.
