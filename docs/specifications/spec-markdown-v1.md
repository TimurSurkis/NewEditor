# Markdown первой версии: поведение, команды и безопасность

Статус: **решения P6.1 зафиксированы; режимы, базовая панель и первый subset структурных абзацных действий P6.2 подключены к файлам; полная визуальная интеграция ещё не завершена**.
Редакция: 2026-11-27.
Основания: [концепция](../concepts/concept-project.md), [архитектура](spec-architecture.md), [контракт редакторов и прототип P3](spec-markdown-editing.md), [файловый UI P5](spec-desktop-ui.md), [план](../trackers/plan-desktop-v1.md).

## 1. Границы и принятые решения

Документ развивает требования первой версии, а не вводит новый формат. Markdown-файл — исходный Unicode-текст с метаданными кодировки. CodeMirror и ProseMirror используют одну DocumentApplication-сессию и историю. Визуальное дерево, DOM, кеш и результаты фонового разбора не становятся сохраняемым содержимым.

Профиль — CommonMark с GFM-возможностями из таблицы ниже, через уже выбранные remark-parse 11.0.0 / remark-gfm 4.0.1. [GFM](https://github.github.com/gfm/) задаёт синтаксический ориентир, но не требует воспроизводить сайт GitHub, его HTML, CSS или сетевые запросы. Математика, диаграммы, сноски, frontmatter и директивы не получают редакторов расширений. Обнаруженные узлы сносок защищаются, даже если парсер их распознаёт. Новые плагины/HTML-сериализатор для P6.1 не добавляются.

- Существующие MD-01–MD-12 остаются неизменными. [MV-01–MV-16](fixtures/spec-markdown-v1-cases.json) — нормативные примеры команд: MV-01/02/05 и отказ MV-16 уже исполняются чистым planner/core в unit-тестах; остальные пока только специфицированы. Сохранение pending при отказе multiline в таблице проверено отдельно GUI. Это не полная приёмка MV/MG.
- Обычные конструкции таблицы должны быть доступны в visual, включая структурные действия. Нельзя закрыть P6.2, оставив все Enter/списки/таблицы в source. Защищённый fallback предназначен для неподдерживаемого синтаксиса или неоднозначного диапазона, а не заменяет согласованные функции.
- Изображения и ссылки отображаются безопасно: нет исполнения HTML и автоматической сети. Чтение локальных изображений реализуется через AssetStore в P6.3; запись/перенос — P6.3/P6.4. До этого image-placeholder честно обозначает недоступный preview.
- В P6 нет неявного форматирования всего документа. Отдельная команда глобального reformat этой минимальной панелью не вводится; если она появится позже, потребуется явное действие пользователя и отдельная спецификация сохранности неизвестных узлов.

Формат новых fixtures: selection.select — единственная подстрока выделения, selection.caretAfter — каретка после единственного вхождения подстроки (ровно один вариант). Action описывает действие драйвера/панели, не IPC/API. ChangeScope — единственная подстрока исходника, внутри которой допустимы изменения; вне неё префикс/суффикс точны. Для rejected changeScope=null и expected=source; errorCode и pending задают ожидаемые отказ/сохраняемый ввод. Исходный status `specified-not-executed` обозначал только спецификацию P6.1; текущий `partially-executed-unit` — частичное исполнение через planner/core, а не прохождение всей MV/MG-матрицы. При реализации адаптер тестов должен выполнить действие, а не вставить expected напрямую. Фактическое покрытие и ограничения ведутся в [отчёте P6](../trackers/track-markdown-v1.md).

## 2. Поддерживаемые элементы

| Элемент | Чтение/отображение | Обязательное редактирование |
| --- | --- | --- |
| Абзацы, пустой документ | Текст, Unicode без NFC/NFD-нормализации, escapes/entities | Ввод/удаление/выделение, вставка plain text, split/join абзаца |
| Soft/hard breaks | Soft break остаётся внутри абзаца; hard break — перенос строки | Enter создаёт новый блок; Shift+Enter — hard break в обычном тексте. Вставка plain text сохраняет логические переводы, не создаёт HTML |
| Заголовки | ATX H1–H6 и Setext H1/H2 | Выбор уровня H1–H6 или «Абзац», ввод текста |
| Inline | strong/emphasis, single/double tilde strike по профилю парсера, inline code | Включение/снятие стиля на выделении, редактирование текста/кода. Новые маркеры `**`, `*`, `~~`, backtick-run |
| Цитаты | Вложенные blockquote с блоками | Включить/снять уровень цитаты; split/join и выход из пустой цитаты |
| Списки | Bullet `-`/`+`/`*`, ordered `.`/`)`, start, tight/loose, вложенность | Создать/снять/сменить вид, split/join пункта, увеличить/уменьшить вложенность, выход из пустого пункта |
| Задачи | `[ ]`, `[x]`, `[X]` в listItem | Переключить checkbox; создать список задач/преобразовать обычный список. Новая задача unchecked |
| Таблицы | Header/delimiter/body, left/center/right/default alignment, escaped pipes | Вставка, текст ячейки, добавить/удалить строку/столбец, alignment столбца; без merged cells, вложенных блоков и multiline-ячеек |
| Блоки кода | Backtick/tilde fences с info string, indented code | Ввод буквального текста/новых строк, вставить/снять code block, изменить язык. `mermaid` и подобные info string остаются кодом, не диаграммой |
| Тематический разделитель | CommonMark thematic break | Вставить и удалить атом как блок |
| Ссылки | Inline, reference/collapsed/shortcut, autolinks и GFM literal autolinks/email | Создать/изменить/снять ссылку; label/URL/title; политика активации в разделе 6 |
| Изображения | Inline/reference image, alt/title и статус preview | Alt/URL/title/удаление ссылки; вставка байтов изображения/preview — P6.3, перенос при Save As — P6.4 |
| Definitions | Определения reference-ссылок/изображений не теряются; связанные употребления отображаются | Редактор definition в исходном режиме; локальная правка label не меняет definition |

CommonMark-нормализация видимого inline code (пробелы/переносы) не даёт права переписать его исходник при переключении. Несовпадающее взаимно-однозначное отображение имеет защищённый участок с переходом к source. Повторяющиеся reference ID разрешаются по семантике парсера, не «исправляются» при чтении. Ссылки на неопределённый ID остаются тем текстом/узлами, которые даёт разбор.

HTML-блок, inline HTML вместе с содержащим абзацем, footnote definition/reference и распознанная неизвестная директива показываются как read-only исходные атомы. Frontmatter-подобный текст без отдельного плагина не интерпретируется как настройки приложения: отображается по разбору либо защищённым исходником, без утраты текста. Неизвестные/неотображаемые узлы имеют явную метку и переход к точному диапазону в source; нет скрытого удаления.

## 3. Панель команд и план правки

Панель доступна Markdown-вкладкам в обоих режимах; в TXT не появляется. Содержит стиль блока, bold/italic/strike/inline-code, quote, bullet/ordered/task-list, indent/outdent, link/image, table, code-block и thematic-break. Структурные/дополнительные настройки могут быть в небольших меню, без отдельного ribbon. Кнопки имеют подписи/aria-label, состояния active/mixed/disabled и объяснение недоступности. Минимальные горячие клавиши: Ctrl/Cmd+B, I, K; сохранение/undo/search остаются P5. В code/opaque они не форматируют скрытый исходник случайно.

Команда получает актуальный исходный текст/разбор, stateRevision, SourceSelection и параметры; выдаёт TransactionBody, selectionAfter и точные затронутые диапазоны либо ошибку. Чистый planner располагается в formats/markdown, без PM/DOM/FS. UI адаптирует действия PM к этому контракту, application проверяет и применяет EditTransaction. Готовый PM-document никогда не сериализуется целиком.

Отказы нового planner описываются собственным чистым типом formats (например, unsupported/invalid-input); модуль не импортирует PortError/application ради кодов ошибок. UI переводит их в CommandError. ErrorCode новых rejected-fixtures относится к результату команды на этой границе, не требует менять ModelError ядра или прежний контракт P3 задним числом.

1. Flush текущей SessionId, завершение текущей группы ввода. Диалог запоминает SessionId, stateRevision, выделение и поколение активации; новый ввод/смена вкладки/ABA после открытия отменяет устаревшую команду с сохранением введённых параметров для повтора.
2. Разбор проверяется по SessionId/sourceRevision **и точному тексту**. Metadata-only кадр не требует повторного разбора, но транзакция использует новую stateRevision.
3. Планировщик проверяет весь диапазон и все параметры до применения. Ошибка не создаёт частичной правки/undo-записи; подходящая source-команда не должна ломать синтаксис, пересекая половину скрытого маркера.
4. Одна команда = одна атомарная транзакция = один шаг undo. Повторное включение уже полностью включённого стиля — no-op; mixed-selection включает стиль во всём допустимом выделении, снятие удаляет только выбранный стиль, не вложенные другие.
5. После применения выделяется исходный диапазон содержимого, не служебные маркеры; insert-команда оставляет каретку в новом содержимом/первой ячейке. Библиотечная собственная история не подключается.

### 3.1. Inline и блоки

- Inline-стили требуют непустого выделения в пределах одного paragraph/heading/tableCell. При каретке без выделения disabled с подсказкой «Выделите текст»; скрытых stored-marks в модели нет. Пересечение code/HTML/opaque или неполных синтаксических маркеров отклоняется целиком. Нельзя создавать вложенную ссылку.
- Inline code допускает однострочное выделение; выбирается backtick-run длиннее максимального run в содержимом. Добавочные внутренние пробелы используются по CommonMark, если нужны для сохранения видимого содержимого; обычная Markdown-пунктуация внутри кода не экранируется. Снятие inline code экранирует содержимое как обычный текст, не включает вложенную разметку случайно.
- Стиль блока действует на текущий блок при каретке, на полностью затронутые совместимые sibling-блоки при выделении. Граница выделения ровно в начале следующего блока не включает его. Несовместимые блоки не пропускаются молча: команда отклоняется целиком с объяснением.
- Новый ATX heading: `#…# ` перед содержимым; новые closing hashes не добавляются. Существующий ATX с closing hashes сохраняет их стиль при смене уровня (MD-12). Setext при изменении уровня нормализуется в ATX внутри этого заголовка. «Абзац» удаляет только heading-маркеры, не inline-содержимое.
- Цитата добавляет/снимает один уровень `> ` для выбранных блоков. Вложенный контейнер может быть нормализован только в пределах выбранной цитаты. Новые разделители строк — preferredLineEnding документа; исходные нетронутые CRLF/CR/LF остаются точными.

### 3.2. Списки и структурный ввод

- Создание/смена вида списка использует `- `, `1. ` с последовательными номерами или `- [ ] `. Явная смена вида/вложенности может нормализовать **минимальный затронутый list-контейнер**, но не соседний список/абзац. Правка текста и checkbox не перенумеровывают соседей; checkbox меняет только символ состояния.
- Enter в непустом пункте делит содержимое и создаёт следующий пункт того же вида/уровня; для новой задачи `[ ]`. В ordered новый номер — номер разделяемого пункта + 1; существующие следующие номера не меняются от одного split. Enter в пустом вложенном пункте уменьшает уровень, в пустом верхнем — выходит в абзац. Indent разрешён при наличии предыдущего sibling-пункта, outdent верхнего уровня выводит выбранные пункты в абзацы.
- Установленный парсер не считает task-маркер без текста (`- [ ] `) завершённой задачей: checked=null, `[ ]` остаётся текстом. При каретке сразу после такого незавершённого префикса planner распознаёт пустой task-пункт по исходнику и применяет те же выход/outdent, а не дописывает ещё один marker. Это не повод менять написание при переключении или подменять канонический текст временным PM-состоянием.
- Backspace в начале непустого пункта соединяет с предыдущим совместимым пунктом; у первого пункта снимает один уровень list. Enter/Backspace не удаляют дочерний список/opaque-соседа незаметно: операция расширяется до определённого контейнера либо отклоняется с сохранённым pending-вводом. Delete симметрично соединяет следующий совместимый блок.
- Enter в обычном абзаце делит его на два; в heading сохраняет левую часть заголовком и создаёт paragraph с правой частью (пустой heading становится paragraph). В quote новый непустой блок сохраняет уровень, Enter в пустом снимает один уровень quote. Backspace на границе совместимых абзацев соединяет их без добавочного символа, сохраняя исходные пробелы содержимого. Shift+Enter вставляет hard break `  ` + перевод строки. В code-block Enter — буквальный перевод; Tab — отступ кода (два пробела для новой вставки), без смены режима. Граница code/opaque не соединяется с обычным текстом неявно: используется явная команда снятия блока/переход в source.
- Plain-text paste в visual трактуется как текст, не HTML: одиночный перенос становится hard break, пустая строка отделяет абзацы, в code-block переводы буквальные; разметочная пунктуация обычного текста экранируется. В source paste остаётся буквальной вставкой Markdown без такого экранирования. Browser text/html, dragged HTML и стили не превращаются в доверенный DOM. Вставка файла/изображения обрабатывается отдельным сценарием P6.3; незнакомые файловые payload не становятся URL.
- Выделенный атом thematic-break/image можно удалить явно; opaque-атом требует перехода в source для удаления. Select-all/cut через opaque не удаляет скрытую разметку молча: предлагается source с исходным диапазоном. Границы Unicode/CRLF остаются правилами core.

### 3.3. Таблица, код, ссылки и изображения

- Новая таблица: диалог положительных rows/columns (rows — число строк данных, минимум 1), явные header-ячейки, строки `| … |`, delimiter `---`, пробел вокруг текста. Заголовки/ячейки по умолчанию пустые; нормализация ширины всех ячеек только при структурной правке таблицы. Размеры запроса проверяются до выделения памяти, максимум 100×100 при создании одной командой; это не лимит читаемой таблицы/документа.
- Добавить строку/столбец — после текущего, новая ячейка пустая. Header не удаляется отдельной командой строки; можно удалить всю таблицу явно. Удаление последнего столбца/последней data-строки отклоняется с подсказкой отдельной команды «Удалить таблицу», не приводит к исчезновению её содержимого. Header-only таблица из файла читается и позволяет добавить первую data-строку. Alignment: `---`, `:---`, `:---:`, `---:`. Текст `|` экранируется `\|`, прежние escapes соседних ячеек не меняются при текстовой правке. Enter/Tab в ячейке переходят в следующую ячейку; Shift+Tab назад (из первой — предыдущий блок), из последней — создаётся строка. Multiline-вставка в ячейку отклоняется с доступным исходным payload, без тихого flatten.
- Новый fenced code использует backticks длиной max(3, максимальный run внутри + 1), info string из диалога без CR/LF/управляющих символов. Для новой language-метки разрешены буквы/цифры/`_+-`; существующая info string сохраняется при правке тела. Fence удлиняется в пределах блока при вставке конфликтующего run. Indented code отображается/редактируется с картой удалённых отступов; снятие блока сохраняет видимый текст как экранированные абзацы.
- Ссылка: диалог label/URL/title; при выделении label берётся из него, при каретке вводится явно и не может быть пустым. Смена URL/title inline-ссылки затрагивает эту ссылку. Для reference-ссылки диалог предлагает преобразовать **это употребление** в inline, не менять общий definition; изменение definition выполняется в source. Редактирование одного label сохраняет исходный reference ID/definition (MD-08). Снятие ссылки оставляет label с его другими inline-стилями; image внутри ссылки сохраняется как image, если такая конструкция была в исходнике.
- Image-диалог изменяет alt/URL/title конкретного image; alt-only не нормализует URL/title (MD-11). Новый URL image допускает относительную цель по правилам resolver либо http/https со статусом недоступного remote-preview; data/blob/file/другие схемы не создаются этой командой. Старый небезопасный URL сохраняется при alt-only и показывает предупреждение. Reference-image при изменении URL/title преобразует только выбранное употребление в inline с явным указанием этого в диалоге. Удаление image меняет текст, но не удаляет физический файл. Жизненный цикл временных байтов, имена assets/rollback и Save As фиксируются перед P6.3/P6.4, не считаются решёнными наличием этого диалога.

## 4. Сохранность исходника и матрица нормализации

| Операция | Максимальная область нормализации |
| --- | --- |
| Текст/IME в отображаемом листе | Однозначно отображённый исходный диапазон; escapes только вставленного текста |
| Inline-стиль/inline-code | Выделенное inline-содержимое и необходимые парные маркеры выбранного узла |
| Heading / label / alt / checkbox | Heading-узел / исходный label / alt / один символ checkbox соответственно |
| Split/join | Два соединяемых/один разделяемый блок и необходимые разделители; для списков их минимальный общий list-контейнер |
| List/quote/indent | Минимальный выбранный list/quote-контейнер с вложенными блоками; исходные opaque-подстроки внутри сохраняются дословно, иначе отказ |
| Table text / structure | Исходный текст ячейки / вся текущая таблица, включая delimiter, но не соседние blank lines/абзацы |
| Code body / смена вида | Тело и при необходимости fences / текущий code-блок |
| URL/title | Конкретная inline-ссылка/image; definition и другие употребления неизменны |
| Переключение/preview/search-find/выделение | Никаких текстовых изменений и версий сохранения |

Каждая правка имеет проверяемые from/to до применения. Если область нельзя доказать, правка отклоняется; нельзя подменять её полной сериализацией. Неподдерживаемые подстроки сохраняются и при нормализации контейнера. Для исходника с смешанными переводами строки нетронутые префикс/суффикс сравниваются посимвольно, затем сохранение проверяется байтово с исходной кодировкой/BOM.

## 5. Файловый workspace, поиск и фоновые результаты

- Расширяется существующий WorkspaceEditor: у каждой Markdown SessionId свой mode, исходное выделение/прокрутка и кеш разбора. Исходный режим по умолчанию, в TXT кнопки режима нет. Переход source ↔ visual не создаёт новую сессию/dirty/undo/SQLite-версию. P3-стенд остаётся изолированным, его контроллер не становится вторым владельцем файлового текста.
- Save/Save As/close/tab/prototype/external-reload используют общий flush активного движка. Незавершённый IME/pending не уничтожается при перестройке PM, смене режима или конфликте. Ввод после захваченного save-снимка остаётся dirty. Сохранение использует source, не отрисованный DOM.
- Поиск остаётся буквальным **по Markdown-исходнику**, как P5, с явной подписью в обоих режимах. Не вводится второй поиск по визуальному тексту с иной семантикой. Видимый однозначный match выделяется в visual; match внутри URL/маркеров/opaque открывает source с точным диапазоном. Replace/replace-all, вызванные из visual, выполняют flush и переход в source, затем ту же атомарную source-замену; подсказка заранее сообщает об этом. Undo остаётся общим, NFC/NFD и `$1` в replacement не нормализуются.
- Результат parse/projection/asset-preview несёт SessionId, sourceRevision, точный исходник либо проверяемый ключ кеша, а также owner/location и поколение режима для зависимых от них операций. Старый результат/ошибка после новой правки, Save As, закрытия или A→B→A не заменяет новый кадр и не показывает preview чужой вкладки. Asset/разбор не меняют stateRevision/dirty.
- При ошибке парсера/проекции source остаётся доступным с точным текстом; не создаётся пустой документ. Визуальные команды старого кадра недоступны до актуальной проекции. Повтор/возврат в source и pending-текст доступны пользователю.

## 6. HTML, URL и ресурсы

### 6.1. Никакого исполнения документа

Не используются innerHTML, HTML→DOM-рендерер или sanitizer как основание доверять документу. Встроенный HTML всегда исходный текст/opaque, включая script/style/svg/iframe/object/form/meta/base, обработчики событий и CSS URL. Paste/drop HTML принимает только plain-text представление, если оно есть; иначе операция отвергается с объяснением. Нет выполнения fenced code, загрузки шрифтов, plugins, диаграмм или автоматического открытия ссылок. Production sandbox/contextIsolation/nodeIntegration=false и ограничения навигации P1 сохраняются.

### 6.2. Ссылки: показ, изменение и активация отдельно

URL из AST — недоверенный ввод, даже если label/значение пришли из reference definition или autolink. В source сохраняется исходное написание; проверка права активации не удаляет/не переписывает его. UI не помещает такой URL в навигирующий href, src, srcset, style или произвольный DOM-атрибут.

| Цель | Действие v1 |
| --- | --- |
| `https:` / `http:` | Только отдельная кнопка «Открыть ссылку» и явное подтверждение с полным нормализованным адресом; main повторно проверяет URL и открывает системный браузер. Обычный click выделяет/редактирует label, а не навигирует Electron |
| Локальный fragment `#…` | Без сети; переход к heading внутри того же документа, не правка. Идентификаторы heading вычисляются отдельно: Unicode lowercase, пробелы/разделители → `-`, удаление пунктуации, суффиксы `-1`, `-2` при совпадении; исходные заголовки не меняются. Не найден — сообщение, не скрытый переход |
| Относительный TXT/MD/Markdown | Явная команда открывает **системный файловый диалог в main** с предложенной целью относительно owner; ref выдаётся только для фактически подтверждённого выбора через существующий open-путь. Для нового несохранённого документа сначала требуется место сохранения/ручной выбор файла. Fragment применяется после успешного открытия |
| `mailto:`, другие схемы, абсолютные файловые/UNC/drive-пути, protocol-relative `//…` | Видимый label/адрес и возможность скопировать; автоматическая и shell-активация в v1 недоступны. Не превращаются в команды ОС |

Для внешнего открытия разрешены только разобранные URL с протоколом http/https, непустым host, без username/password и C0/DEL-символов. HTML entities обрабатываются парсером, но main валидирует значение заново; пробелы/управляющие символы не вырезаются для «исправления» опасной схемы. Создание новой ссылки проверяет эти ограничения/допустимый относительный путь до изменения текста; существующая небезопасная ссылка сохраняется с предупреждением. `javascript:`, `vbscript:`, `data:`, `file:`, `blob:`, пользовательские протоколы и обфусцированные эквиваленты не передаются shell. Переадресации внешнего сайта после подтверждённого открытия — ответственность системного браузера, не разрешение сети renderer.

Heading-anchor — локальное правило приложения, не обещание полной GitHub-совместимости: берётся отображаемый текст heading (включая alt image), Unicode lowercase без NFC/NFD-нормализации; остаются буквы/цифры/комбинируемые знаки, `_`, `-` и whitespace. Группы whitespace заменяются одним `-`, крайние `-` убираются, пустой результат — `section`. В порядке заголовков выбирается первый свободный ID: base, base-1, base-2 и т. д., без коллизий с уже назначенными ID. Fragment декодируется ровно один раз; невалидный percent-encoding/отсутствующий ID даёт сообщение. Пересчёт после правки heading меняет только производную навигацию.

Новые именованные IPC-операции открытия ссылки/подстановки локальной цели вводятся с runtime DTO и проверками WebContents/main-frame/owner только при реализации P6.2. Текущий preload не объявляется уже расширенным. Нет универсальных openPath/openExternal/invoke, принимающих произвольную схему от renderer.

### 6.3. Изображения и CSP

- Внешние http/https images **не загружаются** в v1; показываются alt/адрес и статус «внешнее изображение не загружается». Нет фонового fetch, DNS, remote tracking, remote CSS или превращения URL в локальный файл. Image-вставка из clipboard/drop использует переданные байты, не скачивает адрес из HTML.
- Локальный preview — только через `AssetStore.resolve(owner, relativeUrl, null)` с выданным main owner. Поддерживаются raster PNG/JPEG/GIF/WebP после проверки фактических байтов/MIME, не только расширения. SVG, HTML, PDF и неизвестные типы — placeholder, без декодирования активного содержимого. Исходный Markdown не теряется.
- Область автоматического чтения — поддерево каталога сохранённого документа, не весь диск; это позволяет показывать существующие `images/photo.png`, а не только созданную приложением `.assets`. Запрещены абсолютные пути, URL-схемы, UNC/drive, protocol-relative, `..`, NUL/C0/DEL и query. Путь декодируется ровно один раз, оба разделителя учитываются на всех ОС; encoded separators/traversal не обходят проверку. Разрешённый fragment raster-URL игнорируется для чтения. `%252e%252e` не декодируется повторно. Main проверяет канонический root/target, symlink и замену пути; выход за root отклоняется. Для файлов вне root возможен только отдельный явный выбор/импорт P6.3, не обход resolver.
- Resolver возвращает AssetPayload с проверенным MIME/base64, а не файловый путь. Безопасный preview использует созданный приложением Blob URL; raw document `blob:`/`data:` не принимаются. Blob URL отзывается при смене ресурса/вкладки/закрытии; поздний ответ после Save As не применяется. Отсутствующий/недоступный/повреждённый image сообщает состояние, не меняет source.
- Для одной preview-загрузки вводится защитный предел 20 МиБ; размеры изображения проверяются по ограниченному заголовку **до** полного декодирования: максимум 8192 по стороне и 40 млн пикселей. Это предел безопасного preview, не лимит Markdown-документа. Проверки конкретных декодеров/вставки уточняются перед P6.3.
- В P6.3 production CSP заменяет нынешнее img-src `'self' data:` на `'self' blob:` для проверенных raster-preview; другие директивы ради ресурсов не расширяются. Connect-src для production остаётся без сети, script-src не получает inline/eval; frame/object/navigation остаются закрыты. Dev WebSocket Vite не считается разрешением сетевого доступа Markdown. До реализации preview действующая CSP не ослабляется заранее.

## 7. Производительность: обязательная работа P6.2/P6.5

Проблема P3 — полный синхронный разбор новой ревизии даже для source, около секунды на 1 МиБ. Она не решается переименованием кеша или откладыванием проверки.

План без новых библиотек «на всякий случай»:

1. Source-ввод и metadata/selection не запускают полный Markdown-разбор/PM-проекцию. Разбор ленивый по потребности visual/команды; кеш изолирован по сессии и ревизии.
2. Для visual обычный ввод в однозначном текстовом листе должен обновлять ограниченные координаты/проекцию, а не синхронно сериализовать/перестраивать весь документ. Структурные изменения и глобальные reference-зависимости проверяются полным разбором, если локальность не доказана.
3. Сначала измеряются эти изменения. Если полная проверка всё ещё создаёт длинную main-thread задачу, разбор переносится в Web Worker с явным ревизионным контрактом и индикатором подготовки; нет нового общего серверного/кеширующего стека. До актуальной проекции нельзя отправлять координаты из устаревшего дерева. Отмена ожидания возвращает актуальный source, не теряет ввод.
4. Фиксируются время планирования/apply, parse/projection, main-thread long tasks и наблюдаемое время ввода/переключения. Сравнение с P3 выполняется на тех же детерминированных 10 КиБ/100 КиБ/1 МиБ и на документе с вложенными списками/таблицами/reference.

Бюджеты приёмки на контрольной Linux-машине P3 в **изолированной packaged-сборке**, без параллельного dev-прогона: после прогрева минимум 30 отдельных правок на размер/режим, median/p95. Видимый source/visual-ввод: p95 ≤200 мс на 10/100 КиБ и ≤300 мс на 1 МиБ; нет потерянных правок/undo или main-thread задач >100 мс от синхронного полного разбора на каждом нажатии. Холодная подготовка visual 1 МиБ ≤2 с с доступной отменой/индикатором, повторное переключение без изменения source ≤300 мс. Эти значения — критерии будущей проверки, **не измеренный результат P6.1**. Недостижение требует оптимизации или документированного пересмотра решения до закрытия P6, не скрытого flaky-retry/таймаута. Другие ОС измеряются отдельно в P8; лимит размера документа не вводится.
